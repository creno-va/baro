# V2 official retrieval integration

`createV2LegalRetrieval` is an internal Workers module for #64. It changes neither v1 retrieval nor public routes. The server constructs `now`, `asOfDate` and the typed source plans; model/user URLs are rejected. An article uses a complete bounded eflaw list, exact ID/title and the chosen MST plus effective date and six-digit JO. A list with omitted history is unavailable. Precedents use official list/detail identity, court, case number and decision date. Tax-source HTML-only detail is unsupported. EasyLaw uses an observed title, canonical four-part identity, `ovDiv` text and page-authored basis date; pending updates, omitted substantive images or no date are limited. General search and model memory never supply legal sources.

The official registry is a technical source boundary. It does not establish an account's per-service API activation, legal applicability, human publication approval or complete coverage of a Korean case family. KLAC remains disabled for document-specific rights review; the court help candidate has no verified readable adapter. Official primary guides and copyright provenance are recorded in the registry and [fixture documentation](../../../../../tests/fixtures/legal/v2/README.md).

Callers supply `authorize`, a current owner/consent/revision/tombstone guard, `authorizeQuery`, the #64 privacy-reviewed concept gate, and `reserveRequest`, the actual invocation/attempt cost admission. Never pass original narratives, private names, identifiers, full user chat or raw files as legal queries. `createWorkspaceSourceAuthorization` checks current consent versions, age confirmation, ownership and workspace revision without decrypting case data. Authorization is checked again after reservation before transport, and after public cache storage before binding. Bind citations with the same current workspace guard. Moderator/operator status grants no private case access. Callback failures deny safely. Reservation success does not establish an issued upstream request or an actual charge: if cancellation or revocation denies the final guard, the caller retains and reconciles the unissued reservation through its ledger/expiry rules. This module neither deletes billing evidence, claims zero cost nor charges visible-response quota.

Requests cap six plans, fifty candidate citations, thirty actual external attempts, three attempts per invocation, 2 MiB upstream bodies and total source text, and 1 MiB per normalized source. Fetch and body-read deadlines include stalled streams. Only HTTPS fixed hosts/paths/query shapes are permitted, redirects fail, UTF-8 is checked, and claimed Content-Length cannot bypass the byte cap. No upstream error body, credential, request URL, stack or private query is returned or logged. Source cache stores public normalized text and immutable content identities, never private search queries. After validating the official list, statutes and full-text precedents use the merged #87 bounded discovery query by exact type/official ID/version/section/extractor. It selects fresh rows by fetched time, verification time and deterministic source ID, checks the public body hash and rechecks the latest tuple. Retrieval additionally verifies canonical URL, title, date, court/case number, rights provenance and generated source identity before issuing a fresh workspace citation. No caller-supplied source key/hash is needed. Summary-only precedents and guides are fetched again: the stored public text alone does not establish full-text availability or preserve guide update/image limitations.

Each returned chunk has an independent public source ID, a fresh workspace citation ID, exact UTF-16 source span, source date, SHA-256, extractor version and `applicability: requires_review`. Availability is separate from applicability. `legalSourceStatus` is verified if a verified outcome exists; otherwise unavailable or not_requested. A limited chunk may be displayed with its explicit limitation but must not become a verified fact or report citation. `validateV2Claims` requires verified availability, full source/citation identity integrity and exact Unicode-safe quotation spans. Legal explanations additionally require a server-owned #64 semantic and policy receipt, hashed by `claimReviewHash`; client/model booleans are never approval. Deletion, consent or revision loss prevents releasing retrieval output.

Executed evidence includes real generated SQLite/AES repositories with synthetic owners, consent/deletion races, immutable cache binding, stream/retry/budget/cancellation rejection, captured v1 statute parser inputs, actual EasyLaw structure and public precedent wrapper/types. Provisional synthetic guide selectors and guessed precedent wrappers remain historical preparation examples and are not accepted as production structure. Actual public EasyLaw parsing was checked once; the public precedent example established `PrecService` and documented field types only. Neither validates configured OC, full precedent extraction against captured original text, nationwide coverage or #71 live release evidence. #70/#71 remain the human/public and same-SHA external gates.

Workspace integration binds verified outcomes only. A later limited observation atomically marks older bindings for the same public identity unusable; it preserves facts and binding records. An older observation cannot revoke a newer verification. These availability markers live inside server storage JSON and do not change public contracts or database schema. `official-text-v2-2` is the current extractor policy. Older records remain stored, but cannot regain authority through workspace reload or report export without a new verified lookup. Both paths rebuild the source hash, complete identity, date, rights and 24-hour expiry from the full original and recheck the binding after hashing. Cached report freshness includes this integrity result.

Each chat turn permits one bounded source lookup even if earlier citations exist. The model requests at most two articles per law and uses the server-owned `legal_consultation` guide key, never document IDs or URLs. Model input includes at most ten verified source excerpts of 20,000 UTF-16 units each, with explicit omitted ranges and source limitations. Full originals remain server-side. Structured `sourceClaims` identify exact source spans; the independent gateway audit checks every claim and policy, then the server runs `validateV2Claims` before publishing. A future promulgation date is rejected against the observed server date, independently of the requested historical effective date.

`legal-source-integration.test.ts` and `reports-legal-sources.test.ts` exercise final-digest revocation/cancellation, limited-source reload and downgrade, original/metadata corruption, cached report freshness, excerpt limits and product claim validation. The sixteen family scenarios execute retrieval and chat with attributed factual preparation and source gaps. Their source text is synthetic; these checks do not establish legal applicability or complete family coverage. `legal-readiness-v2.test.ts` also runs all three source kinds in local workerd with synthetic responses. The opt-in readiness CLI covers v2 law, precedent and guide integrity with at most nine reservations; CI receipts identify source tuples and explicitly retain `runtimeWorker: false`. Local synthetic Worker evidence does not replace #71 actual external smoke.
