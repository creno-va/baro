# ADR-0018: 대화 중심 법률 분석·리포트·후속 해결

> 2026-11-08 부분 대체: [ADR-0019](./0019-case-preparation-without-lawyer-platform.md)가 초기 변호사 연결·전용 사용자 단과 변호사와 해결 분기를 제외한다.
> 사건 리포트 반복 확인·문서 우선 시작·민사/형사 세부 흐름은 [검토용 기획](../product/CASE-PREPARATION-SCOPE.md)에서 구분한다.
> 기존 근거 검증·사용자 확인·snapshot·권한/CAS·보존/삭제는 유지한다. 새 제품 구현/배포는 아직 시작하지 않았다.

- Status: Accepted
- Decision scope: 사용자 요청 방향 승인, 구현·실제 외부 인수·독립 법률 승인 별도
- Date: 2026-11-01
- Owners: BARO-REWORK-00 통합, 담당01~06
- Tracking: [#620](https://github.com/creno-va/baro/issues/620), [단일 통합 기록](../development/CONVERSATION-REPORT-REWORK.md)
- Partial supersession: ADR-0006§5의 사실 준비 전용·완성 제출 문서 일괄 금지, ADR-0015의 신규 기능 중단을 이번 사용자 지정 개편 범위에서 대체한다. 기타 운영·공개·권한 경계는 유지한다.

## 맥락

사용자가 직접 고소·청구를 준비하거나 상대방 주장에 대응하는 흐름, 설명에 따른 AI 요약
재조율과 재확인, 자동 법률·판례 조사, 대화 종료 시 근거 있는 리포트, 직접 해결·변호사와
해결·리포트만 저장 및 실제 절차에 맞는 문서 초안을 요청했다. 기존 사실 준비 전용 정책과
소송/협상이라는 단어만으로 정형 거절하는 정책은 이 범위를 충족하지 못한다.

## 결정

1. 사건 목적은 `prepare_claim`, `respond_to_claim`, 구형/미확정 `unconfirmed`로 분리한다.
   개인/기업 `subjectContext`, 사건 분야·형민사, 절차 단계와 혼용하지 않는다. 사용자 확인 없이
   과거 목적·단계를 정하지 않는다. 새 웹 사건은 목적을 명시하고 같은 생성 admission에 저장한다.
2. canonical 요약은 AI 변경 제안과 사용자 확인을 거쳐 갱신한다. 제안 요청·before/after·이유·
   base revisions·확정 receipt를 보존하고 취소·재접속·늦은 완료·동시 변경은 CAS로 처리한다.
3. 검증된 공식 법 조항·요건별 사실/증거·공백/모순과, 유사 판례의 구체적 공통점/차이점,
   우리 측 약점·대응점·보완 자료를 제공한다. 법률 주장은 원문·권한·정확 인용·claim binding·
   의미/정책 독립 감사와 서버 게시 fence를 통과해야 한다. 일반 판례 검색 결과를 바로 승격하지 않는다.
4. 근거 기반 분석과 검토용 문서 초안을 허용한다. 불명확한 절차·관할·기관·기한·법적 결론은
   확인 필요로 남긴다. 공식 절차/서식 근거가 없을 때는 명시적인 사실 정리 초안으로 범위를 표시한다.
   결과·승소 보장, 변호사 사칭, 사실/근거 조작, 불리한 자료 은폐·증거 훼손, 제3자 자동 연락·
   제출·대리 실행은 허용하지 않는다. 단어 기반 blanket refusal 대신 실제 출력과 근거를 검사한다.
5. 대화는 서버가 허용한 액션을 제안하고 명시적 사용자 실행·확인을 받는다. 자료·재조율·리포트·
   후속 선택을 대화 안에서 검토하되 UI를 여는 동작을 자동 제출/새 유료 실행 권한으로 해석하지 않는다.
6. 분석은 별도의 bounded durable 작업으로 준비하고 리포트에 고정한다. PDF/다운로드는 저장된
   분석만 조판하며 새 모델·법률 API 호출을 하지 않는다. 요약·목적·증거·선택/가림 변경은 이전
   결과를 보존하고 새 기준에서 갱신/검토 필요를 표시한다. 검색 실패·자료 부족·관련 판례 없음은
   완료로 위장하지 않는다. 사건 사실 리포트와 법률 분석 완결성은 구분한다.
7. 새 계약 `conversation-report-v1`은 명시적 새 경로/opt-in으로 제공한다. 기존 strict v1/v2
   응답·설치 native client·구형 읽기/삭제·이전 리포트를 보존한다. 필요 없는 새 DB 구조나 추상화를 피한다.
8. 모델은 기존 llm-gateway, 법률 조회는 legal-retrieval 경계를 유지한다. 새 공급자·모델·결제
   경로는 추가하지 않는다. AI200/일·질문2×3·물리/기술 용량·시간/시도 횟수·owner/동의·암호화·
   삭제/revision/lease·독립 audit·비용 관측 전용은 보존한다. 이번 작업은 production에 배포하지 않는다.

## 인수 경계

Accepted는 사용자의 기능 방향 승인이며 법률 검토 통과·정책 초안의 법률 승인·공개 gate 충족이
아니다. 합성/대역 검증과 실제 OAuth·공급자·공식 법률 API·실기기·운영 증거는 구분한다.
담당은 PR을 제출하고00이 검증·순차 병합·브라우저/PDF·최종 main SHA 수동 full을 기록한다.
첫 계약 PR이나 외부 키 없는 offline 성공만으로 전체 개편/전체 MVP 완료를 표시하지 않는다.
