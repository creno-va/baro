# ADR-0015: MVP 운영 기준과 정비 인수 경계

- Status: Accepted
- Date: 2026-10-14
- Owners: hyunhomon (정비 총괄), 기존 모듈 담당
- Partial supersession: ADR-0001/0006의 질문 수, ADR-0013의 AI 응답 수·월 차단·재개 조건, ADR-0005의 운영자 공개 승인 방식, ADR-0007/0014의 디렉터리 조회 구조를 아래 범위에서 대체한다.

## 맥락

공개 서비스를 유지하면서 비용 근거 만료와 미정산 hold가 정상 처리 재개를 막고,
기존 검색의 전체 복호화·페이지 열거와 릴리스의 후보 미결합 증거를 정비한다.
신규 기능 확장은 정비 후로 미룬다. 아래 결정은 구현이나 외부 인수 완료의 증거가 아니다.

## 결정

1. 질문은 최대 2차례×3문항, 계정별 KST AI 하루 200회다. 애플리케이션 월 예산
   차단은 끈다. 기존 공급자·모델·결제 경로와 사용자 설정 자동충전을 유지한다.
2. 관측값 갱신, 같은 할당의 갱신·재개, 할당 변경은 구분한다. 같은 할당의 재개는
   기존 미정산 hold와 실행 작업을 보존하고 현재 revision·유효 근거·보유 노출과
   새 요청 상한을 원자적으로 확인한다. 응답 유실 재시도는 같은 요청으로 복구한다.
   할당 변경은 기존 양 환경 조율을 유지한다. 과거 재원으로 최신 중단·만료를 대체하지 않는다.
3. production은 정확한 SHA에 대해 `hyunhomon` 또는 `hwangeunchan`이 #71에
   기록한 최대 24시간 운영자 승인으로 수동 배포한다. 실제 GitHub Environment는
   보호 브랜치 규칙을 사용하며 필수 reviewer 설정이 있다는 가정은 하지 않는다.
   공개 허가와 독립 외부 검증은 별도 상태다. 초안 수용은 법률 승인으로 바꾸지 않는다.
4. 정식 공개 checker는 후보·환경·검사 종류·결과·실행 reference·산출물 해시를
   검증한다. 출처를 확인할 수 없는 boolean/URL은 증거가 아니다. 이전 SHA의 검증은
   소스·의존성·관련 환경 동일성을 입증하지 못하면 거부한다. 현재 resolver는 보수적으로
   다른 SHA를 거부하며 검증된 producer만 허용한다. 미완료 공개 조건은 계속 실패한다.
5. 최종 main SHA를 명시한 수동 `validate:full`을 한 차례 실행한다. 실제 checkout
   SHA를 증거에 기록하며 유료 호출은 하지 않는다. 같은 SHA의 preview 제한 smoke,
   유효한 운영자 승인 후 production 비공개 합성 고객 smoke를 수행한다.
6. 검색은 공개 목록 projection과 일반 D1 문자 토큰 역색인을 사용한다. 이름·사무실
   부분검색은 후보 조회 뒤 최종 문자열 일치를 확인한다. 지역·분야 필터와 서버 일별
   회전·keyset cursor를 사용한다. 기본 20개, 첫 페이지와 요청한 다음 페이지만 읽는다.
   비공개 초안·사건·자격 자료는 색인하지 않는다. 수정·철회·삭제와 projection을 함께
   갱신하고 응답 직전 공개 권한·revision을 확인한다. 기존 API는 새 조회의 adapter로 남긴다.
7. 고객/변호사 두 역할과 정책 초안 인수를 유지한다. 정비 종료와 전체 MVP 종료는
   별개다. #19/#57/#58 및 디렉터리 #231로 추적하고 새 마일스톤은 만들지 않는다.
   #71은 남은 실제 인수의 담당·필요 증거가 모두 충족될 때만 닫는다.

## 고려한 대안

미정산 비용 삭제, 과거 재원 fallback, 새 외부 검색 서비스, 클라이언트 전체 페이지 수집,
초안의 법률 승인 변환은 채택하지 않는다. 기존 v1 데이터·암호문·삭제 journal은 보존한다.

## 결과

기존 승인 기록과 새 결정의 적용 범위를 분리하고 단계별로 PR·회귀·실제 증거를 남긴다.
소유권·CAS·미정산·late PUT·삭제 복구 계약을 유지하며 `0010`을 다시 쓰지 않는다.

## 후속 및 미결 사항

비용 재개, 검색 구현·100/10,000 D1 비교, 최종 full run, 같은 SHA 배포·합성 자료 정리와
남은 외부 검증은 실제 결과로 판정한다. 지원하지 않는 외부 증거 producer는 실패로 남기며
메타데이터 점검을 실제 OAuth/모델/복구/정책 검증으로 승격하지 않는다.
