# ADR-0020: 절차·입장별 입력과 지속 리포트·목적별 초안

- Status: Proposed
- Date: 2026-11-08
- Authority: 사용자 요청에 따른 네 경로 상세 기획; 구현 승인 전 검토안
- Decision scope: 새 입력/상태/문서 흐름의 아키텍처 제안. 기존 Accepted ADR/strict 계약은 변경하지 않음
- Tracking: [#764](https://github.com/creno-va/baro/issues/764), [상세 사용자 흐름](../product/CASE-PREPARATION-JOURNEYS.md)

## 맥락

민사 청구 준비/대응, 형사 고소 준비/대응은 같은 소유권·자료·근거 검증을 사용하지만
첫 입력과 필요한 사실 확인·문서 종류가 다르다. 모든 사건에 동일한 초기 질문을 강제하거나
상대 주장 문서를 사용자 사실로 저장하면 이해가 틀어질 수 있다. 리포트는 준비 과정에서
계속 열어 확인하고 목적별 초안을 보완하는 기준이어야 한다. 현재 구현의 초안 basis는
report/analysis와 연결되며 검토한 초안만 saved로 저장하는 strict 계약이 있다.

## 제안 결정

1. 계정 역할과 사건의 분야/진행 절차/입장/단계를 분리한다. 네 경로의 공통 저장·권한·
   자료 처리·분석·리포트·초안 경계를 재사용하고 별도 제품/서비스 네 개로 복제하지 않는다.
   구체적 enum/DB 구조와 복합 절차의 저장 단위는 아직 정하지 않는다.
2. 입력은 설명/문서 두 방법으로 받고, 문서 입력에서도 먼저 인증·동의·소유 경계를 확보한다.
   현재 파일 업로드가 사건을 요구하는 사실을 고려해 질문 생성 전 사건 초안 admission을
   분리하는 방향으로 검토한다. 새 endpoint/임시 저장소를 이 ADR에서 선확정하지 않는다.
3. 문서 추출 결과와 원문 위치·coverage를 검토하고 상대 주장/본인 진술/자료 기재/미확인을
   분리한다. 문서 읽기 성공은 사실 확인 성공이나 사용자 확인이 아니다.
4. 확보한 내용에 따라 초기 질문0~2차례×최대3문항을 제안한다. 중복 질문을 줄이되 사용자
   요약 확인·동의/권한·기존 quota/attempt 한도를 우회하지 않는다. 질문 생략 조건·필수
   정보와 기존 client 호환은 후속 계약으로 정한다. 새 문서를 올릴 때마다 intake를 재시작하지 않는다.
5. 사용자 확인 뒤 사실/공백을 읽는 사건 리포트와 법률 분석 준비 상태를 구분한다. 준비 중에도
   리포트를 열 수 있게 하되 분석 미완료/실패·미확인 문서 종류를 완료로 위장하지 않는다.
   최신 사건에서 읽는 화면과 저장된 immutable snapshot·내보내기 버전은 별개로 유지한다.
6. 목적별 초안은 선택한 절차/입장/단계와 저장된 검증 근거를 사용한다. 소장·소장 대응
   답변서·고소장·형사 사실/진술 준비 메모를 우선 상세 설계하고, 다른 단계/문서는 사실
   정리 또는 명시된 제한으로 안내한다. 법률 주장/정확 인용·독립 audit·publication fence는 유지한다.
7. 작성 중 입력 보관과 사용자가 검토한 초안 저장을 분리한다. 임시 보관을 위해 현재
   `reviewed=true`를 위조하거나 기존 saved 상태를 재해석하지 않는다. 실제 작업 중 저장/
   복구의 위치·암호화·소유자 전환·원자성·새 version opt-in 계약은 후속 설계한다.
8. 새 정보와 분석 결과는 기존 초안/리포트에 자동 덮어쓰지 않는다. 기준 revision·자료/분석
   identity·출처 현재성을 확인하고 새 후보와 차이를 검토해 명시 적용한다. 사용자 편집·
   기존 snapshot/PDF와 실패 이력은 보존한다. 사건 변경·출처 만료·직접 편집·분석 누락의 원인을 구분한다.
9. 화면 열기/패널/목차/다운로드는 새 AI/법률 조회의 시작이 아니다. 초안 생성·내용 갱신은
   명시 동작으로 분리하고 기존 자동 분석과의 관계를 후속 계약에서 정한다. 새 생성 단계를
   임의 추가하거나 기술/사용량 한도를 늘리지 않는다.
10. [ADR-0019](./0019-case-preparation-without-lawyer-platform.md)의 변호사 전용 사용자 단/실제 컨택 제외와
    세 액션·미지원 모달, 기존 계정 일반 이용을 유지한다. 제품/API/DB/정책·배포는 이번 단계에서 변경하지 않는다.

리포트 PDF와 현재 초안의 검토용TXT/본문 복사를 구분한다. 초안의 공식 제출 형식 PDF/DOCX
조판을 새로 구현한 것으로 주장하지 않으며 그 출력 확장은 별도 검토한다.

## 고려한 대안

| 대안 | 판단 |
| --- | --- |
| 모든 사용자에게 같은 초기 질문 강제 | 이미 문서에 있는 내용을 반복하고 입장/단계를 놓칠 수 있음 |
| 문서가 있으면 검토/확인까지 모두 생략 | 상대 주장·OCR 오류·누락을 확인 사실로 승격할 수 있음 |
| 네 경로의 저장·API·분석 엔진을 각각 복제 | 공통 보안/근거/자료·리포트 동작이 달라질 위험 |
| 한 개의 가변 리포트를 실시간 덮어쓰기 | 편집·검토·출력의 기준 버전을 보존할 수 없음 |
| 기존 검토 완료 저장 API로 임시 저장 구현 | 사용자가 하지 않은 검토를 기록하게 됨 |
| 문서 선택/다운로드마다 재분석 | 명시 동작·사용량·실패 복구와 저장본 의미가 바뀜 |

## 결과와 전환 경계

문서 우선 intake에는 사건 생성과 질문 생성의 분리, 초안 작업 중 보관에는 기존 검토 완료
저장과 다른 계약이 필요할 수 있다. 이는 현재 API로 이미 가능한 기능이라는 주장이 아니다.
공통 source attribution·요약 확인·분석/리포트/초안 basis·CAS/owner/동의/삭제/lease를
보존하며 설치 client의 strict DTO를 임의로 넓히지 않는다. 정확한 capability/API/DB 변경은
제품 기획 검토 뒤 후속 이슈에서 소유자를 정해 설계한다.

## 후속/미결과 인수

- 질문0회 조건·문서 오분류/판독 실패·확인 전 업로드와 사건 초안 admission.
- 복합 절차의 저장 단위·stage/position 변경과 관련 snapshot의 현재성.
- 작업 중 초안 보관과 검토 완료의 분리·재접속·권한 변경·동시 편집 복구.
- 문서군별 현재 공식 근거/양식·필수 항목·인용·초안 검토/저장/출력의 회귀.
- [J01~J15](../product/CASE-PREPARATION-JOURNEYS.md)의 후속 검증. 현재는 기획 문서이며 시연/실제 법률 인수 성공으로 표시하지 않는다.

Proposed는 검토안이며 제품 구현 권한이 아니다. 비용 관측 전용·AI200/일·초기2×3·
Workers·기존 gateway/retrieval·실제 기술 한도·원장/hold·과거 자료와 인수 이력은 유지한다.
