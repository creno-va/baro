# ADR-0019: 사건 준비 중심 서비스와 변호사 사용자 단 제외

- Status: Accepted
- Date: 2026-11-08
- Authority: 현재 기획 채팅의 사용자 직접 결정 및 기존 계정 일반 이용 유지 확인
- Decision scope: 초기 제품 경계와 문서 우선 작업 승인; 구현·데이터 전환·배포 완료 아님
- Tracking: [#764](https://github.com/creno-va/baro/issues/764)
- Partial supersession: ADR-0006의 변호사 연락 연결, ADR-0007의 디렉터리·등록 제품 범위, ADR-0014의 고객/변호사 이중 사용자 단, ADR-0018의 변호사와 해결 분기. ADR-0008의 공개 프로필 신규 제공 범위는 제외하되 기존 자산의 보관·권한·삭제 의무는 유지한다.

## 맥락

사용자는 초기 서비스에서 변호사 연결과 현존하는 변호사 전용 사용자 단을 제거하기로
결정했다. 자체 디렉터리의 초기 공급 데이터 확보를 현재 제품 목표로 삼지 않는다.
사용자가 쌓인 뒤 로펌과의 계약으로 제공할 기능은 별도 검토하며 현재 제휴로 간주하지 않는다.
제품 코드를 바로 바꾸지 않고 기능 범위·아키텍처 결정·문서를 먼저 정리한다.
추가 확인으로 기존 변호사 계정은 일반 사용자로 본인 사건·자료·리포트를 계속 이용한다.
민사·형사의 다른 진행과정과 입장별 기능은 조사 후 제안받아 검토하겠다고 했다.

## 결정

1. 초기 제품의 사용자 단은 공통 사건 사용자 하나다. 변호사 전용 가입/역할 선택·portal·
   프로필/포트폴리오·공개 목록/검색/상세·연락/길찾기·소개/연결 CTA를 제공 목표에서 제외한다.
   외부 상담 플랫폼 링크나 로펌 목록으로 연결 기능을 대체하지 않는다.
2. 기존 변호사 계정의 계정 식별자·인증 연결·본인 소유 사건/자료/리포트·동의 이력·
   재인증/탈퇴와 삭제권을 보존하고 공통 사건 사용자로 계속 이용할 수 있게 한다.
   직업이 변호사라는 이유로 공통 서비스 이용을 금지하지 않는다.
3. 사건의 준비/대응 입장은 계정 권한과 분리한다. 민사/형사·절차 단계·소유권·개인/기업도
   서로 대체하지 않는다. 이 결정으로 새 enum·테이블·API·migration을 확정하지 않는다.
4. 프로필 UI만 가리고 공개 API/자산을 남기는 것을 제거 완료로 보지 않는다. 후속 구현은
   웹/native/공통 client/서버/공개 자산·캐시/구형 직접 URL을 함께 전환해야 한다.
   종료 응답과 소유자 회수/삭제 경로는 [전환 설계](../architecture/CASE-PREPARATION-TRANSITION.md)에서 검토한다.
5. 현재 단계는 문서만 변경한다. 계정 role 쓰기, 데이터/공개 객체 삭제, API 비활성화,
   공개 정책 버전/동의 receipt 수정, 배포를 수행하지 않는다. 과거 검증/실패·snapshot·
   비용 원장/hold·삭제 journal은 보존한다. 새 제품 범위 구현은 후속 명시 지시 후 시작한다.
6. 향후 로펌 기능은 실제 계약·접수 범위·공유 동의/권한·보관/삭제·운영 책임과 당시 제품
   수요를 확인해 새 ADR로 결정한다. 현재 제휴 예정 기능이나 로펌용 계정/DB/빈 UI를 만들지 않는다.
7. Workers·기존 gateway/retrieval·독립 audit·정확 인용·owner/CAS/암호화/삭제·AI200/일·
   질문 최대2×3·실제 기술 한도와 비용 관측 전용 정책을 유지한다. 법률/공개 승인을 만들지 않는다.

## 고려한 대안

| 대안 | 판단 |
| --- | --- |
| 디렉터리와 변호사 계정을 유지하며 초기 공급 확보 | 사용자가 초기 범위에서 제외하기로 결정 |
| 로펌 목록 또는 외부 플랫폼 연결로 즉시 교체 | 연결 기능 제거 결정을 충족하지 못하며 현재 제휴 근거 없음 |
| 화면에서만 숨기기 | 직접 URL·API·공개 자산·설치 client의 제공이 남음 |
| 변호사 계정과 데이터를 일괄 삭제 | 일반 이용 유지 확인 및 소유 데이터 보존과 충돌 |
| 미래 로펌용 조직/권한 구조 선구축 | 계약·수요·책임이 미결이므로 현재 구현 근거 없음 |

## 결과

제품의 중심을 사건 이해·증거 정리·준비 문서·반복 검토에 둔다. 일반 사용자 전환은
가입 흐름만의 수정이 아니며 세션·공통 client·공개 projection·객체 권한을 함께 검증해야 한다.
기존 데이터 보존을 구실로 공개 연결 기능을 계속 제공하거나, 기능 종료를 구실로 소유 데이터를
삭제하지 않는다. 종전 ADR은 당시 결정과 증거로 보존하며 이 문서의 대체 범위만 우선한다.

## 후속과 미결

- [기능 범위와 검토용 제안](../product/CASE-PREPARATION-SCOPE.md): 민사/형사 × 준비/대응, 문서 우선 진입, 지속 리포트와 목적별 초안.
- [전환 설계](../architecture/CASE-PREPARATION-TRANSITION.md): 기존 role·구형 계약·공개 자산·원격 데이터의 안전한 전환. 정확한 저장/응답 방식은 미결.
- 민사·형사 4경로의 세부 기능, 첫 문서 종류/절차 범위, 기타 분야 지원 수준은 사용자 검토 전 제안이다.
- 문서 작성 완료는 기능 제거·기존 계정 전환·로펌 계약·실제 법률/외부/배포 인수 완료가 아니다.
