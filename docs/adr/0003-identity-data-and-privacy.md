# ADR-0003: 인증, 데이터와 개인정보 보호

- Status: Accepted
- Date: 2026-10-04
- Owners: Engineering, Product

## 맥락

사건 서술과 분석 결과에는 민감한 개인·재산·분쟁 정보가 포함될 수 있다. 재열람 기능을
위해 저장은 필요하지만, 비밀번호를 직접 다루거나 원문이 로그·DB·외부 분석 도구에
평문으로 확산되는 위험을 줄여야 한다.

## 결정

- Better Auth를 자체 호스팅하고 Drizzle adapter로 D1에 연결한다.
- 로그인 공급자는 Google과 Kakao다. 비밀번호 인증과 게스트 사건은 제공하지 않는다.
- 이용자는 만 14세 이상을 스스로 확인한다. 생년월일은 저장하지 않는다.
- 계정과 사건은 최초 출시부터 저장한다.
- 사건 원문, 추가 답변, AI 결과는 AES-256-GCM으로 애플리케이션 계층에서 암호화한다.
- 키는 버전별 Worker secret으로 관리하고 D1에는 키 버전, 임의 IV, 인증 태그가 포함된
  암호문만 저장한다. 검색·목록에 필요한 최소 메타데이터만 평문으로 둔다.
- 인증된 사용자와 리소스 소유권을 모든 API에서 서버가 확인한다.
- 사건은 사용자가 삭제할 때까지 보관한다. 사건 삭제는 관련 분석·인용을, 계정 삭제는
  인증 데이터·세션·사건을 운영 D1에서 삭제한다.
- 원문과 결과는 애플리케이션 로그, AI Gateway payload log, 제품 분석 이벤트에 남기지
  않는다.
- 공개 전 개인정보 처리방침과 국외 이전·처리위탁 내용은 법률 검토를 통과해야 한다.

## 고려한 대안

- 비로그인 로컬 저장: 재열람과 기기 간 사용은 쉽지 않고 민감 데이터 잔존을 통제하기
  어렵다.
- D1 평문 저장: 구현은 단순하지만 DB 열람 또는 백업 노출의 영향을 키운다.
- 필드 검색 가능한 결정적 암호화: 검색 요구가 없고 동일 값 노출 위험이 있어 제외한다.
- 별도 KMS 서비스: 키 수명주기에는 유리하지만 MVP 운영 복잡도가 커 secret 기반
  버전 키로 시작한다.

## 결과

- OAuth 공급자 설정과 고정 preview 콜백 관리가 필요하다.
- 키 분실은 복구 불가능하므로 백업·회전 절차와 최소 접근 통제가 필요하다.
- 암호화 필드는 DB 검색·정렬에 사용할 수 없다.
- 법적 보관 의무가 새로 확인되면 삭제 범위와 공개 정책을 함께 바꾸는 ADR이 필요하다.
