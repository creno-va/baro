# 웹 프론트 재구성 범위

2026-11-16 사용자 요청에 따라 최신 main `b54566f3`에서 웹 프론트를 새로 구성한다.
작업 결과는 별도 브랜치와 PR로 검토하며 이 문서는 배포·실제 외부 인수 완료를 뜻하지 않는다.

## 제품 경계

새 화면은 `src/components/web/`, `src/client/query/`와 웹 전용 스타일을 사용한다.
`src/pages/`의 공개 페이지와 사건 경로는 새 문서 레이아웃과 React 화면으로 연결한다.
이전 React 화면·레이아웃·랜딩 스크립트는 제품 진입점에서 제거한다.

백엔드, DB와 migration, API 계약, 작업 처리, 인증·권한, 저장·삭제 동작은 이 개편의
교체 대상이 아니다. `src/server/`, `src/contracts/`, `src/workflows/`, `src/worker.ts`,
`apps/mobile/`, `packages/api-client/`, `packages/client-core/`의 경계를 유지한다.
웹 API 어댑터는 공유 클라이언트의 소유권 확인, 취소, revision, 멱등성 및 처리 복구를
계속 사용한다. 조회를 취소해도 이미 접수된 서버 작업이 취소되는 것은 아니다.

## 기본 UI와 상세 화면 계획

이 PR은 새 기본 UI와 주요 API 연결의 첫 검토 단위다. Astro 문서 안에서 하나의 React
작업 공간을 실행하고, Tailwind·CVA·clsx·tailwind-merge로 컨트롤 변형을 구성한다.
버튼과 모달 primitive는 Tailwind Labs의 Headless UI를 사용한다. 아직 전역 client state가
필요하지 않아 Zustand를 추가하지 않으며, 공유 계약의 Zod 검증은 유지한다.

사용자가 선택한 구조는 **대화 중심 + 사건별 자료·리포트**다. 사이드바에서 사건을 고르고,
본문의 대화·자료·리포트로 이동한다. 질문·사건 요약·타임라인·다음 행동은 해당 사건의
맥락 안에서 연다. 모바일은 사건 목록을 모달로 열고 같은 작업 화면을 사용한다.

| 작업 | 이번 기본 UI | 후속 상세 인수 |
| --- | --- | --- |
| 시작·접근 | 개인/기업 사건·입장·서술 생성, 기존 소셜 로그인·동의 | 실제 공급자 로그인과 계정 변경 브라우저 인수 |
| 대화 | 저장된 대화·이전 메시지, 자료 선택·전송·실패 재확인, 공식 근거 읽기 | 인용 위치·맞춤 외부 조회·촬영·대화 첨부 세부 UX |
| 사실 확인 | 질문 저장·모름/건너뛰기·다음 질문, 요약·사실 상태, 수정 제안 비교·확인 | 장기 처리·동시 편집·수정 취소의 전체 브라우저 시나리오 |
| 자료 | AI 처리 안내 확인, 파일별 업로드·진행·재시도, 관찰 내용·원본·삭제 | 관찰 내용 교정·미디어 재생·출처 이동과 대용량 상세 검토 |
| 리포트 | 명시적 준비, 버전 검토·편집·개인정보 가림·자료 제외·사진 선택·PDF | 전체 문서 레이아웃·공식 근거·저장 후 후속 해결 화면 |
| 사건 관리 | 제목 변경·명시적 삭제, 기존 v1 기록 읽기 | 타임라인 추가/교정·다음 행동 상세 편집 |
| 계정 | 실제 사용량·로그아웃·재인증·계정 삭제 | 두 역할·동의 철회·실제 삭제 정리 전 과정 |
| 랜딩 | 새 문서/스타일 경계와 시작 링크를 검토하는 임시 랜딩 | 기존 랜딩의 시각 참조를 확인한 후 같은 디자인을 새 구조로 재현 |

Codex 앱 직접 제어는 Computer Use의 앱 접근 정책에 의해 거절됐다. 따라서 앱을 직접
조작해 시각 일치를 확인했다고 주장하지 않는다. 새 랜딩·로그인·접근 상태는 로컬
브라우저에서 확인한다. 테스트용 합성 계정의 정책 동의 제출도 승인 심사에서 거절되어,
명시적 허가 전에는 해당 제출이나 이를 우회한 인증 후 화면 조작을 수행하지 않는다.

## 조회 상태와 성능 작업 경계

TanStack Query의 키는 소유자·로그인 세대·사건·자원으로 나눈다. 한 작업 공간에서
미완료 조회를 공유하고, 계정·동의 상태 변경 시 이전 캐시와 응답을 폐기한다. 포커스 복귀는
세션 확인에 성공한 뒤 활성 자원만 갱신한다. 변경 요청은 자동 재시도하지 않으며, 불확실한
결과는 같은 입력과 멱등 요청으로 확인한다. 진행 중인 작업만 활성 화면에서 관측한다.

API/DB 지연 개선은 다음 검토 단위에서 합성 여정의 HTTP·SQL 호출 수와 처리 시간을
먼저 측정한다. 세션/권한 확인·revision/CAS·멱등성·삭제 경계를 유지하면서 중복 projection과
불필요한 왕복을 줄인다. 이번 조회 계층 정리나 단위 검사 결과를 원격 지연 개선 수치로
표현하지 않으며, 이번 PR에는 백엔드·DB·공유 모바일 클라이언트 수정이 없다.

## 기존 URL

| 경로 | 새 화면 연결 |
| --- | --- |
| `/new` | 새 사건 |
| `/app`, `/cases`, `/cases/new` | `/new`로 이동 |
| `/cases/:caseId` | 대화 |
| `/cases/:caseId/files` | 자료 |
| `/cases/:caseId/reports` | 리포트 |
| `/cases/:caseId/timeline` | 타임라인 |
| `/cases/:caseId/actions` | 다음 행동 |
| `/cases/:caseId/summary`, `/cases/:caseId/intake` | 질문과 요약 |
| `/cases/:caseId/precedents` | 사건 대화 |
| `/lawyers`, `/lawyers/:id`, `/lawyer` | 기존과 같은 제공 종료 안내, HTTP 410 |

사건 ID는 공유 계약으로 검증한다. 비공개 화면의 `private, no-store`와 서버 접근 제어,
CSP 아래 Zod 초기화는 유지한다. 두 계정 유형 모두 본인 작업 공간을 이용하는 현행 동작을
예전 고객 전용 제한으로 되돌리지 않는다.

## 이전 화면의 테스트 보존

이전 시각 컴포넌트는 `tests/helpers/retired-web/components/`, 레이아웃은
`tests/helpers/retired-web/layouts/`로 옮긴다. 해당 디렉터리의 `BaseLayout.astro`는
개편 전 main의 문서 래퍼를 복사한 테스트용 snapshot이다. 이전 랜딩 스크립트와 스타일은
같은 디렉터리의 `baseline-client/`, `baseline-styles/`로 옮긴다.
기존 테스트의 실제 import만 새 경로로 연결하며 개발 검사기의 가상 경로 입력은 유지한다.

이전 화면을 불러오는 fixture·단위 검사는 과거 동작의 회귀 자료다. 이를 실행한 결과를 새
화면의 브라우저 인수 결과로 표시하지 않는다. 새 화면은 새 진입점과 조회 계층을 대상으로
검증하고 실제 OAuth·AI·파일 처리·배포 증거와 합성 로컬 확인을 구분한다.

다음 소스는 기존 경로를 유지한다.

- `src/components/reports/document.ts`, `download.ts`, `review-sections.ts`: 서버의
  리포트 생성·마스킹 및 원문 구성에서도 사용하는 비시각 처리 함수.
- `src/components/reports/download-reviewed.ts`, `orientation.ts`: 검토한 리포트
  버전과 소유권 확인 및 문서 읽기 보조 함수.
- `src/components/ui/unavailable-document.ts`: 서버 인증 장애 응답의 독립 문서 생성기.
- `src/components/` 아래 나머지 `.ts` 보조 함수: 이전 fixture와 단위 검사의
  사건·자료·타임라인·오류·진행 상태 계산을 유지한다. 새 화면의 시각 컴포넌트는 아니다.
- `src/styles/global.css`, `product.css`: 공유 모바일 design token 추출의 정본.
- `src/styles/`의 나머지 기존 팔레트·화면 CSS: 이전 fixture와 팔레트 검사에서 참조하는
  호환 소스. 새 `BaseLayout.astro`는 이 스타일을 가져오지 않는다.

제품 소스는 `tests/helpers/retired-web/`를 import하지 않는다. 실제 외부 설정이 없는
실패 상태를 예시 응답으로 바꾸지 않으며 합성 adapter는 명시적 로컬 검사에서만 사용한다.
