조회·내보내기·삭제는 유지한다. P01~P04는 새 구현 작업을 시작할 근거가 아니다.

## 2. 초기 제품에서 제공할 것과 제외할 것

| 구분 | 범위 |
| --- | --- |
| 유지 | 일반 로그인/동의·본인 사건·대화·사실/타임라인·자료 처리/검토/교정·공식 근거 분석·준비 행동·리포트·검토용 초안·PDF·설정/삭제 |
| 제외 목표 | 변호사 역할 선택/가입·전용 portal·프로필/포트폴리오 관리·공개 목록/검색/상세·연락처/길찾기·실제 연락/소개·관련 메뉴/랜딩 유도 |
| 유지할 진입 | 리포트의 직접 해결/변호사와 해결/리포트만 저장. 변호사 액션은 실제 기능 없이 미지원 모달만 표시 |
| 대체하지 않음 | 외부 변호사 플랫폼 연결, 상담 예약/접수/자동 자료 전달, 모집/수임/추천·성과 순위 |
| 보존 의무 | 기존 계정/인증 연결·본인 사건/자료/리포트·동의/삭제 이력·과거 검증/실패·비용 원장/hold |

사용자가 직접 파일을 저장하고 선택한 상대에게 전달하는 일반 내보내기는 유지한다.
공식 절차의 한계나 전문가 검토 필요성에 대한 사실 안내까지 지우는 결정은 아니다.
그 안내를 변호사 탐색·외부 플랫폼 연결 CTA로 바꾸지 않는다.

### 리포트의 세 액션과 미지원 모달 (확정)

현재 제품의 `직접 해결`/`변호사와 해결`/`리포트만 저장` 세 액션을 유지한다.
사용자가 표현한 '변호사와 진행'은 기존 `변호사와 해결` 액션을 가리키며 명칭 변경은 요구하지 않는다.
다른 두 액션의 준비/저장 동작과 권한·동의·현재성·busy 가드는 유지한다.

- 변호사 액션은 비활성 버튼으로 숨기지 않고 클릭 시 미지원 모달을 표시한다.
- 문구 제안: 제목 `아직 지원하지 않는 기능이에요`, 본문 `현재 변호사 연결 기능은 제공하지 않습니다.`, 버튼 `확인`.
- 연락처·외부 사이트·공유 범위·접수/신청·출시 일정/예정 문구는 제공하지 않는다.
- 이 클릭은 로컬 UI 동작이다. 새로운 선택을 저장하거나 선택 revision/보고서/초안/자료를 변경하지 않고, 실제 연결·자료 전송·AI/법률 API를 실행하지 않는다.
- 기존 직접 해결 선택·미저장 입력/초안·사진·리포트 편집·스크롤을 유지한다. 과거에 저장된 변호사 선택 이력도 자동 변경/삭제하지 않는다.
- 공통 Dialog의 키보드 포커스·Escape/닫기·스크린리더 안내를 따르고 닫으면 누른 액션으로 포커스를 돌린다.

실제 모달 구현과 기존 선택/편집 보존·네트워크 mutation0 검증은 후속 제품 작업이다.

## 3. 제안: 계정 유형 대신 사건의 절차와 입장으로 분기

사건 내용의 분야(예: 대여금/임대차/일터 문제), 진행 절차(민사/형사/미확인), 사용자 입장,
실제 진행 단계, 보유 문서와 자료를 서로 다른 정보로 다룬다. 일터 문제라는 이유만으로
민사/형사 중 하나를 확정하지 않는다. 아래는 제품 기획의 개념 이름이며 새 wire enum이 아니다.
직접 판단하기 어렵다면 미확인으로 시작해 AI 제안·사용자 확인을 거친다.
준비/대응 선택만으로 원고·피고·피의자·피고인이나 범죄 성립을 확정하지 않는다.

첫 화면에서 법률 분류 시험을 요구하지 않는 방식을 제안한다. 자신의 요구를 준비하는지,
받은 요구/통지에 대응하는지와 보유 문서부터 입력하고, 절차·단계를 제안받아 확인할 수 있다.
사용자가 원하면 알고 있는 절차를 직접 선택한다. 다른 절차나 양쪽 입장을 추가할 가능성도
막지 않으며 소송 전 사용자를 이미 원고/피고로 부르지 않는다.

| 경로 제안 | 첫 입력 | 주 기능 | 우선 검토할 초안 |
| --- | --- | --- | --- |
| 민사 · 청구 준비 | 원하는 해결·사실·금액과 계산 근거·약정/거래 자료 | 청구 항목/이유와 증거 연결, 상반 자료와 부족한 사실 확인 | 사실 정리, 소장 검토용 초안 |
| 민사 · 청구 대응 | 받은 소장/지급명령/요구 문서 또는 본인 설명 | 상대 요구/주장 추출, 인정/다툼/모름별 본인 설명·자료 연결 | 받은 문서·절차에 맞는 답변 준비/답변서 검토용 초안 |
| 형사 · 고소 준비 | 피해로 설명하는 경위·상대 정보·자료 | 주장 사실과 증거 위치 연결, 기억/추론/미확인 구분 | 고소장 검토용 초안 |
| 형사 · 고소·수사 대응 | 보유한 고소장/출석요구/통지 또는 알고 있는 내용 | 통지/상대 주장과 본인 설명 구분, 실제 단계·자료 확인, 조사 준비 사항 | 사실관계·진술 준비 메모; 단계별 의견 문서는 후속 검토 |

민사 대응 문서를 모두 답변서로, 형사 대응 문서를 민사식 답변서로 통일하지 않는다.
소장·지급명령·출석요구·공소장 등은 문서 종류와 현재 단계를 확인한 뒤 기능을 제안한다.
초안 명칭만 제공하고 실제 법정 서식/절차가 완성됐다고 표시하지 않는다.
공식 근거·사용자 확인·기존 독립 audit와 인용 검사를 통과한 범위만 작성한다.

### 받은 문서로 시작하는 흐름

1. 문서가 있으면 선택해 업로드하고, 없으면 알고 있는 내용으로 시작한다.
2. 문서 종류·보낸 곳·상대의 요구/주장·관련 사실·명시된 날짜를 추출한다. 원문 위치·미처리 범위를 함께 보여준다.
3. 사용자가 추출 오류·일부 문서/별지 누락을 확인한다. 첨부만으로 모든 주장을 확인했다고 표시하지 않는다.
4. 상대 주장마다 본인의 입장을 인정/다툼/모름 등으로 설명하고 근거 자료를 연결한다. 상대 주장을 본인 진술이나 확인 사실로 저장하지 않는다.
5. 이미 확보한 정보는 재질문하지 않고 중요한 공백만 질문한다. 일반 질문 0회 가능 조건은 요약 확인과 별도 설계한다.
6. 사용자 요약 확인 후 공통 작업공간을 이용한다. 사용자 확인은 사실의 진실성·자백·제출 서명이 아니다.

질문이 필요한 경로는 기존 최대2차례×3문항을 유지한다. 0회 제안으로 한도를 늘리지 않는다.
문서가 없거나 판독에 실패해도 새 사건을 처음부터 다시 만들도록 강요하지 않는다.
형사 대응에서 고소장 사본 보유나 자동 송달을 전제하지 않는다. 문서 접근 가능 여부는
각 사건의 실제 상태로 확인하며 문서 자동 취득 기능을 이번 범위에 추가하지 않는다.
문서에 적힌 날짜, 사용자가 기억하는 받은 날짜, 법적 기한 계산은 다른 정보다.
일정 추출을 기한 확정으로 표시하지 않으며 기산점/예외/현행 근거 확인과 자동 계산 기능은 미결이다.

### 민사·형사가 함께 관련되는 상황

하나의 사실관계가 두 절차와 관련될 수 있으므로 AI가 사용자를 한 분야로 강제 확정하지 않는다.
민사 청구와 형사 절차의 목적·상대 주장·단계·문서·확인 근거를 섞지 않는 방식을 제안한다.
한 사건 안의 절차별 보기와 별도 사건 연결 중 어느 구조를 쓸지는 미결이며 DB 구조를 선확정하지 않는다.
형사 고소로 민사 회수가 완료되거나 어느 한 절차 결과가 다른 절차의 결과를 보장한다고 안내하지 않는다.

## 4. 제안: 지속 리포트와 목적별 문서 초안

| 대상 | 역할 | 갱신/보존 원칙 |
| --- | --- | --- |
| 사건 리포트 | 현재 이해한 사건·쟁점·근거·상반 내용·부족한 자료·준비할 일의 지도 | 준비 중 언제든 열어 확인. 저장 snapshot과 현재 사건의 차이 표시 |
| 목적별 초안 | 선택한 절차/입장/단계에 맞는 문서 작성과 검토 | 문장·주장과 사실/증거 연결. 사용자 편집·검토 이력 보존 |
| PDF | 선택해 검토한 특정 버전의 휴대/보관용 결과물 | 같은 저장본 본문·사진·출처 유지. 웹 화면 없이 읽을 수 있어야 함 |

리포트는 사건 이용 종료 조건이 아니다. 대화 ↔ 자료/사실 검토 ↔ 사건 리포트 ↔ 목적별
초안을 오가며 준비한다. 상세 화면의 세 작업 화면/자료 보조 패널·왕복/주요 액션은
[화면 구조 v0.1](../design/CASE-WORKSPACE-LAYOUT.md)에 구체화한 검토안이다.
직접/변호사/저장의 세 액션은 리포트에 유지하되 준비를 끝내야만 사용할 수 있는 필수 관문으로 두지 않는다.
변호사 액션은 위 미지원 모달만 열며 실제 연결 분기로 진행하지 않는다.

새 자료·요약·입장/절차 변경은 영향 범위를 표시한다. 리포트 열기·메뉴 전환·다운로드만으로
새 AI/법률 API를 실행하지 않는다. 새 분석과 리포트 반영 시점·확인 방식은 후속 계약으로 정한다.
원문 확인 기간 경과와 사용자 내용 변경, 분석 일부 미완료, 본문 직접 편집을 구분해 설명한다.
이전 snapshot/초안/PDF를 덮어쓰거나 stale 검사를 약화하지 않는다.

## 5. 조사 근거와 적용 한계

기한·관할·제출처·양식 인수를 확정하지 않는다. 현재 BARO의 검증 citation/snapshot으로

## 6. 상세 기획과 다음 검토

초기 입력→문서 추출/검토→질문0~2×3→요약 확인→반복 리포트→목적별 초안은
[네 경로 상세 기획](./CASE-PREPARATION-JOURNEYS.md)에 화면·입력·예시 질문·리포트
내용·문서 종류/제공 조건·예외·J01~J15로 구체화했다. [ADR-0020](../adr/0020-procedure-aware-intake-and-working-reports.md)은
문서 우선 admission·출처 구분·작업 중 보관/검토 완료 분리·snapshot의 아키텍처 검토안이며
Proposed다. 현재 strict API/DB와 초안 저장 기능을 이미 바꾼 것으로 표시하지 않는다.

## 7. 기획 검토 시나리오와 완료 구분

- 문서 없는 준비 사용자와 문서 있는 대응 사용자를 각각 끝까지 설명할 수 있어야 한다.
- 소장/고소장/출석요구 등 문서 오분류·판독 실패·별지 누락·문서 없음의 복구 흐름을 명시한다.
- 상대 주장 인정/다툼/미확인·상반 자료·다중 절차를 확정 사실과 섞지 않는다.
- 자료 보완 뒤 리포트 확인·초안 수정·재접속·PDF 보관을 반복할 수 있어야 한다.
- 변호사 연결 없이도 준비를 계속할 수 있고 기존 변호사 계정의 본인 데이터가 보존돼야 한다.

현재 완료는 D01~D04와 제안/미결 기록을 구분한 문서화다. 미지원 모달·시나리오 실행·제품 변경·
계정 전환·공개 기능 종료·실제 법률/외부 인수는 후속 구현/검증 전까지 미완료다.
