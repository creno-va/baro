# BARO v2 전체 서비스 기능 명세
> **2026-10-06 사용자 개정 — 아래 이전 범위보다 우선한다.** MVP는 고객/변호사 두 역할이며 통합 로그인에서 선택한다. 변호사 승인 어드민·자격 심사·반려·승인대기 UX는 제외한다. 실제 제품 client UI 동일 구현체를 API mock adapter로 먼저 완성하고 기능 연결을 병렬 진행한다. 별도 /mock UI는 만들지 않는다. [5세션 계획](../development/PARALLEL-UI-SPRINT.md)의 실제 착수부터 2시간 sprint를 적용하며 독립 UI는 DB/AI/OAuth/backend CI/A 이슈 종료를 기다리지 않는다. 완료된 코드/이슈/증거를 보존하고 새 DB/비용 선행 이슈를 추가하지 않는다. AI 품질 확대는 모든 UX 연결 뒤다. P0.3/#70/#71 외부·정책·production·공개 gate는 보존하며 mock 성공을 실제 외부 성공으로 표시하지 않는다. [ADR-0014](../adr/0014-mvp-two-roles-and-api-mock-first.md)가 대체 범위를 기록한다.

## 현재 구현과 전환

v1은 개인 간 대여·한 묶음 최대 다섯 질문·구조화 결과·저장·삭제다.
기존 schemaVersion 1 데이터·읽기·삭제·기존 인용을 보존한다. v2는 독립적인
workspace/version 계약과 additive schema로 확장하며 기존 사건을 자동 재분석하지 않는다.
제품 목표 변경이 이미 배포된 v1의 기능 확대를 뜻하지 않는다.

## 공통 조건

- 대한민국 사건 가족 전체, 개인 또는 기업 단일 작성자 소유, 만 14세 이상.
- 공개 디렉터리 읽기 외 사건 변경·자료·AI 사용은 로그인·현재 동의·소유권을 요구한다.
- 재동의 전에도 자신의 과거 데이터 조회·다운로드·삭제와 로그아웃은 가능해야 한다.
- 소유권·revision·고객/변호사 role·공개 동의·quota는 서버가 검사한다. role 선택으로 moderator 권한을 부여하지 않는다.
- 사건 데이터는 암호화하고 모델로 보내는 식별 정보를 최소화한다.
- API/DB/Workflow/UI는 shared strict 계약을 사용하고 v1 타입을 느슨하게 바꾸지 않는다.
- JSON body 한도와 자료 upload 한도를 구분하고 파일 확장자/클라이언트 MIME만 신뢰하지 않는다.

## 질문·요약·chat 상태

```text
draft → intake_saved → questioning → summary_pending → confirmed → active_workspace
                       ↖ answer_revision / pause_resume      ↖ summary_reconfirmation
어느 단계에서도 safety_redirect / dependency_failed / usage_waiting / deletion 가능
```

질문마다 answered/unknown/skipped를 구분해 저장한다. 세 묶음을 다 써야 하는 것은
아니며 이미 충분하면 요약으로 이동한다. 기본 초기 cap 15개 이후 공백은 표시하고
chat 에서 질문한다. 반복 질문으로 초기 폼을 무한히 늘리지 않는다.
v1의 24 시간 만료 때문에 v2의 저장된 질문·답변을 지우거나 새 사건 생성을 요구하지 않는다.

요약 확인은 법률적 사실 인정이나 제출 서명이 아니다. 사용자가 내용을 확인했다는
revision 기록이며 새 사실/자료가 핵심 요약을 바꾸면 변경 표시와 재확인을 제공한다.
자료 분석·채팅 생성 작업의 상태와 사건 상태를 분리해 한 실패가 전체 자료를 잃게 하지 않는다.

## 준비 행동·법률 경계

행동은 자료 찾기/보유 확인, 날짜·발언·약속의 출처 확인, 사실 공백을 상담 질문으로
만들기, 상담 자료 정리 등 승인된 범주에 한정한다. 자료 진정성·증거능력·승패·
손해액/기한의 확정적 계산·법적 주장/협상/소송 전략·완성 제출서류 자동 작성은 제공하지 않는다.
긴급 안전 안내는 일반 진행보다 우선하며 공식 도움 경로를 사용한다.

공식 근거 조회 실패 시 factual 정리·파일 검토·사실 리포트는 계속 사용할 수 있지만
새 법률 설명·공식 출처처럼 보이는 인용은 만들지 않는다. 세무·형사 등 분야를 통째로
범위 밖 처리하는 v1 screening을 그대로 새 사건에 사용하지 않는다.

## 자료·리포트 한도

| 한도 | 값 |
| --- | --- |
| 사건 원본 수/합계 | 100개 / 5GB |
| 문서·이미지 한 파일 | 100MB |
| 음성·영상 한 파일 | 1GB, 60분 |
| PDF 한 파일 | 500쪽 |
| 계정 전체 보관량 | 10GB; 원본·파생물·저장 리포트 포함 |
| KST 하루 | 신규 사건 3, 사용자 AI 응답 30, 음성/영상처리 합계 60분 |
| 월 기술 비용 | 1,000,000 원; 법률 검토 별도 |

서버는 byte(1MB=1,000,000, 1GB=1,000,000,000) 경계를 검증하고 duration/page를
처리 admission 단계에서 확인한다. duration를 아직 모르면 예약/검증 중 상태로 두며
검증되기 전 모델 처리를 시작하지 않는다. 손상·보호 파일·지원 불가 codec은 명시적 오류다.
제품에 문서·이미지·음성·영상 네 범주의 실제 지원을 구현해야 하며 지원하지 않는
세부 형식은 공개된 형식 목록과 UI 에서 구분한다. 형식 목록은 구현 계약에서 고정한다.

음성은 전 구간 전사를 목표로 하고 영상은 전 구간 음성·1초 간격 및 장면 전환
프레임을 결합한다. 작업을 chunk로 나눠 provider 한도를 지키며 실제 coverage를 기록한다.
누락 구간은 리포트에서도 표시한다. 실제 시간 비용과 retry 비용은 월 ledger에 포함한다.

요청 재생·자동 retry로 사용자 quota를 다시 소비하지 않는다. 새로운 사용자 메시지/
새 자료와 동일 작업 retry는 논리 operation ID로 구분한다. 내부 질문 생성은 사용자
AI 응답을 따로 늘리지 않지만 실제 비용은 모두 계산한다. quota 차감/반환 시점은
[실행 계약](../architecture/DOMAIN-LIFECYCLE.md#v2-사용량과-비용)의 v2 정본을 따른다.

리포트는 사실성·출처·참조 자료의 고정 revision 으로 만든다. 식별자가 있는 PDF 와
마스킹하지 않은 원본 ZIP을 구분해 설명한다. 사용자가 이름 등을 가리면 PDF 생성
내용에 반영하고, 원본 자체를 바꿨다고 주장하지 않는다. 선택 제외된 파일은 ZIP 과
해당 리포트 참조 범위에 반영한다. 다운로드는 인증·owner·삭제 가드와 private URL 수명을 가진다.

사용자에게 표시한 질문 묶음·요약·채팅·AI 자료 해석의 논리 응답 작업은 각각 1회다.
묶음 안 질문 수와 내부 phase 호출은 추가 사용자 응답으로 세지 않는다. 단순 텍스트
추출·이미 생성한 snapshot의 PDF/ZIP 다운로드는 AI 응답을 소비하지 않으며 실제
비용은 모든 호출/처리마다 월 ledger에 기록한다.

## 자기 프로필 상태 (ADR-0014)

```text
통합 로그인: customer / lawyer → 해당 dashboard / 자기 portal
자기 프로필: 작성 → 저장 → 미리보기 → 수정 / 삭제
공개 프로필: 실제 공개 동의·소유권·개인정보 경계 적용, 확인되지 않은 자격 인증 표시 없음
```

승인 어드민·자격 신청·반려·재신청·승인대기는 MVP에서 제외한다. 기존 서버 심사 계약은
역사와 기존 데이터 보존을 위해 유지한다. 공개할 자산을 사용자가 명시적으로 선택하며
private 사건 자료를 프로필에 자동 공유하지 않는다. 실제 서비스 공개/법률·정책 승인은 #70/#71 별도다.

## 삭제·복구와 v1 회귀

새 삭제 job은 source object·derivative·report·temporary export·processing context를
누락하지 않게 추적한다. CAS/FK 와 삭제 guard를 external call 전후에 검사한다.
정리 실패는 재시도/경보를 남기며 목표 기간 경과만으로 미완료 journal을 제거하지 않는다.
백업 복구는 최신 journal 재적용 후 traffic을 연다.

v1 사건은 기존 read/answers/retry/delete 의미와 schemaVersion 1을 유지한다.
v2 작업 공간과 함께 목록에서 구분해 열 수 있고 migration이 기존 데이터를 훼손하지
않아야 한다. 과거 완료 사건에 사용자 승인 없는 모델 호출·비용을 만들지 않는다.

v2 전환 후 신규 사건은 모두 v2 경로로 생성한다. v1의 과거 일 10회 생성 계약은
역사/회귀 기록이며, 새 서비스에서 v1 생성 경로를 우회해 일 3 사건 한도를 늘릴 수 없다.
기존 진행 중 v1 답변/retry는 유지하되 실제 비용은 공통 월 예산에 포함한다.

## 전체 완료 판정

[UI 시연](./UI-DEMONSTRATION.md)의 정상·실패·권한·persistence·다운로드 시나리오,
자동 테스트·CI·schema drift/fresh/upgrade·Worker bundle, 실제 외부 연동 및 같은 SHA
preview/production 증거가 모두 필요하다. 승인되지 않은 정책·사업자 사실·자격·행동
범주를 승인된 것으로 표시하면 완료 실패다. public gate 미충족은 미완료 상태로 유지한다.
