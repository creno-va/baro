## 7. 파기 절차와 방법

계정 삭제는 실제 OAuth 재인증 10분 이내와 명시적 DELETE 확인을 요구합니다. 운영
DB의 계정·동의·사건·분석·인용·피드백 및 모든 세션 삭제와 durable journal 기록을
원자적으로 처리하여 세션을 즉시 revoke하고 202를 반환합니다. 202는 primary 삭제
접수이며 모든 백업·Workflow 상태의 즉시 제거 완료를 뜻하지 않습니다.

Workflow active/completed 저장 상태는 공유 scheduler가 bounded 재시도·backoff로
비동기 정리합니다. 실패 작업은 보존하여 운영 조치를 요구합니다. journal은 원문 없이
opaque 식별자·상태만 보관하지만 가명정보로 다룹니다. 백업 복구 시 DB 밖에 보관한
최신 journal을 서비스·cron/dispatch 재개 전에 재적용하여 데이터 부활을 차단합니다.
암호화 키·백업 접근 제한과 실제 플랫폼 보존·격리 복구 drill은 공개 전 검증 대상입니다.

## 10. 쿠키와 유사 기술

로그인 세션과 보안을 위해 필수 쿠키를 사용합니다. 현재 선택 사용 지표는 명시적 동의
후 해당 탭의 sessionStorage에 최대 500개 허용 이벤트·무작위 분석 ID·탭의 무작위
salt 및 사건 ID의 HMAC hash만 보관합니다. 이는 익명정보가 아닌 가명정보입니다.
사건 내용·이메일·인증 ID·토큰·자유 의견을 수집하지 않으며
외부 분석 공급자로 전송하지 않습니다. 거부해도 사건 기능을 이용할 수 있고, 동의
철회 시 선택 지표·ID·salt와 진행 중 기록 상태를 삭제합니다. 브라우저 세션 복원은
탭 종료 이후에도 sessionStorage를 복원할 수 있어 절대적인 종료 시 삭제를 보장하지
않습니다. account_deleted도 opt-in이 유지된 경우에만 기록됩니다. 도움 여부 boolean은
지표 동의와 독립적인 선택 요청으로 D1에 보관하고 사건/분석/계정 삭제 시 cascade로
지웁니다. 지표 철회를 D1 도움 여부 삭제로 표현하지 않습니다.
`[PUBLICATION_BLOCKER: 선택 사용 지표의 목적·가명정보 분류·sessionStorage/브라우저 복원 보존 및 고지 승인]`
공개 전 실제 쿠키와 유사 기술의 이름, 목적, 제공자와 기간을 서비스 화면에서 확정합니다.
