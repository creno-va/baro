# 사건 쟁점 기반 관련 판례 탐색

- 사용자 직접 요청: 2026-10-21 현재 정비 채팅.
- 작업: [#308](https://github.com/creno-va/baro/issues/308).
- 선행: [PR306](https://github.com/creno-va/baro/pull/306)의 CI 성공 및 main 통합.
- 현재 단계: 선행 승인 대기 중 독립 wire 계약·합성 fixture·설계. 제품 endpoint/서비스/UI는 미구현.

## 사용 흐름

확인한 v2 사건의 메뉴에 ‘판례’를 추가한다. 별도 페이지로 구성해 대화 composer/첨부 흐름과
분리한다. 데스크탑은 검색 주제·결과 목록과 판결문 검토 영역을 나란히, 모바일은 목록 아래
선택 판례를 표시한다. 키보드/스크린리더에서도 결과 선택과 원문 이동을 사용할 수 있게 한다.

1. 현재 확인 요약에서 공개 법률 쟁점을 추천한다. 사실관계의 확정 판단이 아니라 **검색 주제 제안**이다.
   추천이 없으면 사용자가 검토된 주제 목록에서 선택할 수 있다. 최대2개 주제를 선택한다.
2. 사용자가 ‘관련 판례 찾기’를 누를 때만 공식 API를 조회한다. 자동 반복/스케줄/모델 호출은 추가하지 않는다.
3. 목록에는 사건명·법원·사건번호·선고일·확인 시각, 검색에 사용한 쟁점, 검증 원문 발췌를 표시한다.
   유사도 백분율이나 승소/동일 결과를 표시하지 않는다. 검색 일부 여부와 확인 못한 주제를 구분한다.
4. 결과 선택 시 해당 원문의 제한된 본문을 읽고 공식 전체 원문을 새 창에서 열 수 있다.
   ‘같은 쟁점이어도 계약 내용·경위·증거·판단 시점이 다를 수 있어요’와 비교할 자료 안내를 제공한다.

추천은 확인 요약의 명시된 쟁점과 검토된 별칭을 서버에서 대응한다. 모호한 부분은 미확인 상태로
유지한다. 개인 사건과 판례의 사실관계를 AI가 완전히 비교했다고 표시하지 않는다. 선택한 공개
주제와 판결문 내 단어 일치만 설명하며 실제 적용 여부는 원문 검토/전문가 상담 대상으로 남긴다.

## 개인정보와 원문 검증

- 외부 query는 서버가 주제ID에서 변환한 공개 법률 개념뿐이다. 사건 원문·사람 이름·연락처·회사명·
  파일 본문·모델 생성 자유 검색어를 보내지 않는다. request에는 revision과 allowlisted topic ID만 허용한다.
- 기존 `legal-retrieval/v2`만 공식 서버를 호출하며 PR306의 법원 corpus 필터를 사용한다.
  목록/상세 식별자·법원·사건번호·선고일·본문/hash 검증을 통과한 원문만 결과로 제공한다.
- 본문은 plain text로 표시한다. 발췌는 정확한 UTF-16 span과 전체 길이·잘림 여부를 보존한다.
  표시 가능한 발췌와 실제 적용성 판단을 혼동하지 않는다. 미지원/검증 실패·빈 검색 결과를 구분한다.
- 검색은 최대2개 주제×3개 판결문, 외부 요청은 전체12회·120초 안에서 수행한다. 재시도도 횟수에 포함한다.
  모델 호출이 없으므로 새 모델·유료 AI 실행/일일 quota 차감 경로를 추가하지 않는다. 기존 요청 rate limit은 유지한다.

## HTTP와 접근

wire schema는 `src/contracts/v2/precedent-research.ts`다. 독립 계약 작업 중에는 API에 연결하지 않는다.

| 경로 | 내용 |
| --- | --- |
| GET `/api/v2/cases/:id/precedents` | 확인된 최신 사건 revision·summary revision·제목·추천 주제 |
| POST `/api/v2/cases/:id/precedents/search` | 버전과 선택 주제 확인 후 검증 결과 목록 |
| POST `/api/v2/cases/:id/precedents/read` | 해당 검색 결과의 제한된 원문 발췌 |

각 요청은 고객 역할·현재 동의·소유권·살아 있는 사건·현재 확인 요약을 검증한다. 새 검색은
`expectedRevision`과 `summaryRevision`을 모두 요구한다. revision/동의/역할/삭제는 외부 요청 직전과
최종 응답 전에 다시 확인한다. 미로그인·타인 사건·검증 실패·변경된 요약에는 새 검색을 하지 않는다.

공식 public 원문 cache만 재사용한다. 판례 탐색을 기존 채팅의 자동 근거 추가로 취급하지 않는다.
목록 읽기를 위해 사건 DB에 별도의 검색 기록/원문 사본을 저장하거나 새 schema를 만들지 않는다.
검색 결과의 readToken은 기존 서버 secret에서 목적을 분리해 서명한 짧은 만료 증명으로,
소유자·사건·revision·source ID/hash·인용 metadata와 결합한다. upstream 키가 아니며 임의 source ID를
읽는 권한으로 쓰지 않는다. 읽기 시 현재 접근과 원문 무결성을 다시 확인한다.

페이지 결과·토큰·선택 상태는 메모리에만 유지하고, 로그아웃/동일 브라우저의 계정·동의 변경 시
즉시 제거한다. 늦게 온 응답은 화면에 복구하지 않는다. 일반 focus는 선택을 유지하되 현재 세션을
검증한다. API는 private/no-store이며 사건/검색 주제/원문/토큰을 진단 로그로 보내지 않는다.

## 병행 작업과 검증

새 `precedent-research` 서비스/API/클라이언트/컴포넌트/CSS와 전용 page를 우선 사용한다.
공유 연결은 API router와 CaseNavigation의 판례 메뉴로 최소화한다. Workspace.tsx·composer와
client/api/types.ts는 수정하지 않는 방향으로 첨부 #307 담당에게 전달한다.

소유권·동의·역할·삭제·revision race, 악의적 query/URL/토큰, 캐시 원문/metadata 변조, 만료,
요약 재확인 필요 상태, 무응답/429/5xx/빈 결과/부분 결과·취소를 실제 SQLite/API 테스트로 검증한다.
브라우저는 데스크탑/모바일·키보드·긴 판결명/원문·로딩/실패·목록/본문·계정 전환을 확인한다.
실제 공식 서버 요청과 합성 UI/fixture 결과 및 배포 Worker 결과는 별도 기록한다.
