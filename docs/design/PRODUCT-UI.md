# 제품 화면 UI 개편

2026-10-22 · [#332](https://github.com/creno-va/baro/issues/332). 랜딩과 `/app`의 브랜드를 기준으로 제품 화면의 정보 위계와 레이아웃을 정리한다.

## 근거와 적용

토스의 [디자인 시스템 설계 사례](https://toss.tech/article/toss-design-system)는 반복 패턴의 일관성, 긴 텍스트와 다양한 화면 크기, 접근성을 컴포넌트에서 함께 처리한다.
[Value first, Cost later](https://toss.tech/article/value-first-cost-later)는 사용자에게 행동을 요구하기 전에 얻을 가치를 이해시키는 원칙이다.
BARO에서는 아래와 같이 해석해 적용했다. TDS 컴포넌트나 브랜드 자산을 복제하지 않는다.

| 점검에서 발견한 문제 | 제품 화면의 변경 |
| --- | --- |
| 작은 사건 카드의 열기·삭제 영역이 겹침 | 한 열의 읽기 목록과 독립된 삭제 영역으로 분리 |
| 반복 제목·장식·카드 때문에 실제 내용이 아래로 밀림 | 제목·설명·주 행동의 위계를 통일하고 구분선 중심의 섹션 사용 |
| 모바일 사건 제목과 여러 줄 메뉴가 입력창을 밀어냄 | 제목 두 줄 제한, 한 줄 가로 탐색, 사건 관리는 제목 옆 메뉴로 이동 |
| 901px에서 사이드바가 나타나 검색·본문이 급격히 좁아짐 | 제품 화면은 1100px까지 상단 탐색 사용, 검색은 컨테이너 폭에 맞춰 재배치 |
| 공개 프로필의 이름·사진·연락 정보가 분산됨 | 프로필 헤더에 사진·이름·사무소·분야를 묶고 연락처 바로가기 제공 |
| 설정·요약·리포트에 모든 설명과 편집 항목이 동시에 노출됨 | 설정은 섹션, 요약은 사실별 수정 펼치기, 리포트는 읽기 → 선택적 수정 → 다운로드 흐름 |

법률·개인정보 고지와 오류, 동의·소유권·revision 확인, 저장·삭제·재시도·파일 선택은 기존 계약을 유지한다. 리포트 읽기 본문은 React 텍스트로 출력하고 문서 흐름으로 스크롤한다. 편집 중 초안은 포커스 복귀 시 보존하며 소유자 변경 시 편집 상태도 초기화한다.

## 적용 경계

`src/styles/product.css`는 `.app-frame.app-frame--product` 안에서만 작동한다. `AppLayout`의 `conversation-main`에는 이 클래스를 추가하지 않는다. 랜딩의 코드·스타일·자산, `global.css`와 `/app` 입력 구현은 변경하지 않는다.

제품 본문은 최대1100px, 사건 작업·리포트는 최대840px의 읽기 열을 사용한다. 기존 버튼·카드·세션/API 구현을 재사용하고 표현 계층에서 조합한다. 모바일의 사건 탐색은 영역 안에서만 가로 스크롤되며 문서 전체에는 가로 스크롤을 만들지 않는다. 키보드로 모든 메뉴에 접근할 수 있고 현재 메뉴는 진입 시 보이도록 맞춘다.

## 모바일 구현에 인계할 기준

[ADR-0017](../adr/0017-expo-mobile-and-shared-client-boundaries.md)의 웹 디자인 정본 원칙에 따라 다음 의미를 전달한다. 이번 변경은 `apps/mobile`, 공유 계약과 root workspace 설정을 수정하지 않는다.

| 의미 | 웹 값/규칙 |
| --- | --- |
| 주 행동·선택 | `--product-blue: #2364e8` |
| 본문 | `--product-ink: #191f28` |
| 보조 표면 | `--product-subtle: #f6f8fb` |
| 약한 구분선 | `--product-line: #edf0f4` |
| 주요 모서리 | `--product-radius: 20px` |
| 조작 영역 | 주요 버튼·사건 탐색 최소44px, 큰 텍스트는 줄바꿈 허용 |
| 정보 위계 | 내용·진행 상태 우선, 선택적 관리·기술 설명은 펼치기 |

네이티브 화면은 이 의미와 흐름을 따르되 웹의 CSS·DOM 구조를 공유하지 않는다. 실제 기기·VoiceOver·TalkBack 인수는 모바일 작업 범위다.

## 재현과 검증 범위

`bun ci`, `bun run validate:quick`, `bun run validate:build`와 변경 흐름의 기존 브라우저 회귀 검사를 실행한다. 세부 실행 결과·정확한 검증 SHA는 #332와 구현 PR에 기록한다.

새 `tests/browser/product-ui.config.ts`는 320/390/768/900/901/1024/1440px의 사건 목록·검색·설정·대화·자료·타임라인·리포트, 조작 영역 분리, 모바일 입력창·사건 탐색, 요약 수정, 리포트 초안 보존, axe와200% 텍스트를 검증한다. 검토용 합성 캡처는 `.wrangler/ui332/`에 저장한다.

브라우저 검사는 합성 세션·자료·대역 API를 사용한다. 실제 OAuth·AI·외부 처리·원격 성능·production 배포와 MVP 전체 인수를 뜻하지 않는다.
