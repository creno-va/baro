## 1. 배치의 기본안

한 사건 안에서 `대화`/`리포트`/`문서 초안`을 항상 보이는 세 작업 화면으로 두고,
`자료`는 어느 화면에서든 여는 보조 패널로 둔다. 자료를 여는 행동과 주 작업 화면을
바꾸는 행동을 구분한다. 리포트/초안 진입을 자료 패널이나 대화 액션 안에만 숨기지 않는다.

| 영역 | 역할 | 기본 규칙 |
| --- | --- | --- |
| 앱 사이드바 | 새 사건·최근 사건·계정/설정 | 현재 사건 표시, 접기 가능. 변호사 전용/탐색 메뉴 제외 목표 |
| 사건 헤더 | 사건명·절차/입장/단계·사건 도구 | 모든 작업 화면에서 같은 사건임을 확인. 미확인 단계는 미확인 표시 |
| 작업 화면 선택 | 대화 / 리포트 / 문서 초안 | 현재 화면 표시, 준비 전에도 진입해 상태/부족 항목 확인 |
| 주 작업 영역 | 현재 선택한 대화 또는 문서 | 읽기/입력에 충분한 폭, 화면별 스크롤과 입력 보존 |
| 자료·근거 패널 | 사건 자료 목록·선택 자료 검토·원문 위치/근거 발췌 | 한 번에 하나의 보조 내용, 주 작업을 유지하며 열기/닫기 |

기존 요약·타임라인·다음 행동·판례는 사건 도구와 본문의 관련 링크로 접근한다.
그 기능까지 다시 여섯 개 가로 탭으로 늘리지 않는다. 세 작업 화면 선택은 앱 전체의
별도 내비게이션이 아니라 같은 사건의 작업 전환이다. 새 SPA/상태관리 도구 도입은 결정하지 않는다.

## 2. 데스크톱 와이어프레임

아래는 개념 배치이며 구현된 화면/정확한 픽셀 검증 증거가 아니다.

### 대화

```text
┌ 앱 탐색 ─────┬ 사건명 · 민사/청구 대응 · 단계 확인          [사건 도구] ┐
│ 새 사건      │ [대화]  리포트  문서 초안                    [자료 3] │
│ 최근 사건    ├─────────────────────────────┬──────────────────────┤
│ 현재 사건    │ 현재 필요한 확인/진행 상태    │ 자료·근거            │
│              │                             │ [자료 추가]           │
│              │ 사용자 메시지·답변          │ 자료 A · 검토 필요    │
│              │ 쟁점/자료/리포트 연결        │ 자료 B · 처리 중      │
│              │                             │ 자료 C · 검토함       │
│              │                             │                      │
│ 설정·계정    │ 첨부·선택 자료 / 입력 / 보내기│ 선택 자료 검토/원문   │
└──────────────┴─────────────────────────────┴──────────────────────┘
```

### 리포트

```text
┌ 앱 탐색 ─────┬ 사건명 · 절차/입장/단계                     [사건 도구] ┐
│              │ 대화  [리포트]  문서 초안                    [자료]   │
│              ├─────────────────────────────────────────────────────┤
│              │ 사건 리포트 · 작성 기준 / 반영 필요 상태              │
│              │ [변경 내용 반영]  [본문 편집]  [PDF 저장]            │
│              ├─────────┬──────────────────────┬────────────────────┤
│              │ 목차    │ 지금 내 사건         │ 자료·근거           │
│              │ 접기    │ 지금 준비할 일       │ 클릭한 주장/자료의  │
│              │         │ 쟁점·내 설명·근거    │ 쪽/시간·원문 범위   │
│              │         │ 약점·미확인·출처     │                    │
│              │         │ [직접 해결][변호사와 해결][리포트만 저장]   │
└──────────────┴─────────┴──────────────────────┴────────────────────┘
```

자료 패널은 닫을 수 있다. 중앙 폭이 부족하면 목차를 본문 위 펼치기로 바꾼다.
자료와 목차를 모두 펼치기 위해 읽기 열을 지나치게 좁히지 않는다. 리포트의 세 액션은
본문의 다음 준비 영역에 두며, 모든 문단을 읽어야만 버튼이 생기도록 하지는 않는다.

### 문서 초안

```text
┌ 앱 탐색 ─────┬ 사건명 · 절차/입장/단계                     [사건 도구] ┐
│              │ 대화  리포트  [문서 초안]                    [자료]   │
│              ├─────────────────────────────────────────────────────┤
│              │ 소장 초안 ▾ · 작업 중 보관 상태 · 기준 리포트        │
│              │ [현재 사건 반영]  [검토 후 저장]  [본문 복사/저장]   │
│              ├─────────────────────────────┬──────────────────────┤
│              │ 확인할 항목/빠진 내용        │ 자료·근거            │
│              │                             │ 선택한 문장에 연결된 │
│              │ 문서 본문 읽기·편집          │ 사실/자료/기준 절    │
│              │                             │ [원문에서 확인]      │
│              │ 관련 사실/자료로 이동        │                      │
└──────────────┴─────────────────────────────┴──────────────────────┘
```

문서 목록을 별도 영구 사이드바로 또 추가하지 않는다. 초안이 없으면 문서 선택/준비 조건을
주 작업 영역에 표시하고, 있으면 마지막 작업 문서를 이어 연다. `다른 문서`/문서 제목 선택에서
종류·작성 중/저장 버전을 바꾼다. 한 번에 한 문서만 주 편집 대상으로 둔다.

## 3. 크기별 배치와 스크롤

| 환경 | 배치 제안 | 자료·근거 / 목차 |
| --- | --- | --- |
| 넓은 데스크톱 | 기존256px 사이드바(접힘64px), 유동 본문, 보조 패널360px 기준 | 패널을 연 뒤에도 중앙 작업 폭640px 이상 확보될 때 나란히 표시 |
| 1200px 이상이나 중앙 폭 부족 | 본문 우선, 사이드바 접기 가능 | 자료는 겹쳐 여는 방식. 목차는 펼치기; 두 보조 열 때문에 읽기 폭을 강제로 줄이지 않음 |
| 768~1199px | 사이드바 rail/서랍, 중앙 한 작업 화면 | 자료 보조 화면/패널, 문서 목차는 펼치기 |
| 768px 미만 | 앱 메뉴 버튼·작은 사건 헤더·세 화면 선택·본문 | 자료는 전체 높이 보조 화면, 원문/교정은 그 안의 다음 단계로 이동 |

640px은 본문과 자료를 함께 읽기 위한 초안 기준이며 실제 시각/확대 검증 후 조정한다.
기존 token/폰트/공통 버튼·Dialog를 사용한다. 다른 브랜드나 별도 디자인 시스템을 만들지 않는다.
첫 대화 진입의 넓은 화면에서는 자료 패널을 보여주는 안이며, 좁은 화면에서는 닫힌 상태다.
이후에는 같은 사건에서 사용자가 열고 닫은 상태를 존중하고 화면 전환만으로 패널/모달을 새로 띄우지 않는다.
근거 링크를 누른 것은 해당 자료·근거를 여는 명시 동작이다.

- 대화: 메시지만 내부 스크롤, 입력창은 중앙 영역 아래에 유지. 지난 메시지를 읽을 때 새 답변으로 강제 이동하지 않는다. 필요하면 `새 답변 보기`를 표시한다.
- 리포트/초안: 긴 문서의 자연스러운 세로 읽기를 우선한다. 헤더/작업바가 본문을 계속 가리지 않게 하고 이중 스크롤을 최소화한다.
- 자료 패널: 독립 스크롤. 어느 본문에서 열었는지와 자료 쪽/시간 위치를 유지한다.
- 리포트 목차: 공간이 충분할 때만 본문 옆에 표시하고 좁으면 펼치기로 전환한다. 자료가 추가된다는 이유로 본문 읽기 위치를 위로 보내지 않는다.
- 화면 확대·모바일 키보드·가로/세로 전환으로 입력/자료 교정/파일 선택/진행 상태를 remount해 잃지 않는다.

### 모바일 와이어프레임

```text
메뉴   사건명                              자료 3
민사 · 청구 대응 · 소장 내용 검토 중
대화          리포트          문서 초안
────────────────────────────────────────────
현재 주 작업 하나
대화: 메시지 + 하단 입력
리포트: 접이식 목차 + 본문 + 준비 액션
초안: 문서 선택 + 편집 + 보관/검토 상태
────────────────────────────────────────────
자료 열기 → 전체 높이 자료 보조 화면
뒤로: 리포트로 / 자료 목록 / 선택 자료 원문
```

하단에 네 개의 앱 메뉴를 또 붙여 대화 입력창과 경쟁시키지 않는다. 세 화면 선택은 사건 헤더
아래에 유지하고 가상 키보드가 입력을 가리지 않게 한다. 긴 사건명은 줄임 처리하되 전체 이름을
확인할 수 있어야 한다. 자료/앱 탐색 서랍을 동시에 주 보조 화면으로 열지 않는다.
자료 안에서 원문/교정을 열면 같은 보조 화면의 내부 이동으로 표현한다. 삭제 등 확인 Dialog는
최상단 확인에만 초점을 두고, 닫으면 이전 자료/입력 위치로 돌아간다.

## 4. 대화 화면의 내용과 주요 액션

### 기본 구성

상단에는 현재 필요한 확인이나 실제 진행 작업을 필요한 경우에만 표시한다. 메시지마다
중복된 준비 상태 카드를 붙이지 않는다. 답변에는 해당 사실·자료 위치와 `리포트에서 보기`/
`문서 초안에서 보기`처럼 대상을 알 수 있는 링크를 둔다. 아직 생성되지 않은 문서를 있는
것처럼 표현하지 않고 `초안 준비 조건 보기`로 연결한다.

| 주요 액션 | 실제 의도 | 화면에서 보여줄 결과 |
| --- | --- | --- |
| 보내기 | 입력/선택 자료를 명시적으로 대화에 전달 | 원래 입력·작업 상태·실패 재시도, 중복 전송 방지 |
| 자료 추가 | 파일 선택/검토 후 기존 업로드/처리 | 자료 패널과 진행 상태. 선택만으로 전송/반영했다고 표시하지 않음 |
| 리포트에서 보기 | 관련 절을 읽기 | 리포트로 전환해 해당 절 강조, 대화 초안/스크롤 보존 |
| 문서 초안에서 보기 | 기존 문서 또는 준비 조건 확인 | 초안 모드의 해당 문서/절. 자동 생성 없음 |
| 다른 부분 설명 | 현재 요약/사실의 보완 | 기존 재조율·확인 흐름. 메시지 전송/정본 변경을 자동 실행하지 않음 |

초기 질문/요약 확인이 남은 사건에서는 그 작업을 중앙에서 이어가며 전체 사건을 다시 만들지 않는다.
리포트/초안 진입은 가능하되 가능한 조회와 현재 부족한 조건을 보여준다. 필수 확인 전 새 생성/
수정을 허용하는지 여부는 기존 server guard와 후속 계약을 따른다. 과거 본인 저장본의 허용된
조회/다운로드·삭제를 초기 질문 완료 요구로 막지 않는다.

## 5. 자료·근거 패널의 내용과 주요 액션

### 세 가지 보조 보기

1. `사건 자료`: 자료 추가·목록·처리 상태·실제 처리 범위·선택 상태.
2. `선택 자료`: 원본·쪽/시간·추출 내용·교정/검토·처리 실패/재시도·삭제.
3. `연결된 근거`: 현재 본문에서 누른 자료 위치, 저장된 리포트 절/근거 발췌와 기준. 자료/원문 전체로 이어짐.

세 보기는 같은 보조 패널 안의 전환이다. 자료 목록 옆에 원문, 그 옆에 교정창을 연속으로
추가하지 않는다. 자료 목록으로 돌아가기와 패널 닫기를 구분한다. 공식 법률 출처는 검증된
저장 발췌를 보여주고 `공식 원문 열기`를 사용자가 선택한다. 일반 검색 결과를 검증 근거로 표시하지 않는다.
좁은 패널에서 원본이 읽기 어려우면 `크게 보기`로 기존 자료 뷰어를 넓혀 열고, 닫으면
동일 본문/쪽/시간으로 돌아온다. 원문을 보기 위해 공개 링크를 만들지 않는다.

| 액션/상태 | 뜻 | 혼동하지 않을 것 |
| --- | --- | --- |
| 업로드/처리 중 | 비공개 자료 저장·자동 추출 진행 | 사건 요약·법률 분석 반영 완료가 아님 |
| 자료 확인/교정 | 추출 내용과 원본 대조·수정 | 보고서 본문 편집이나 원본 파일 수정이 아님 |
| 대화에 사용 | 다음 대화의 맥락으로 선택 | 전체 사건 정본에 이미 반영됐다는 뜻이 아님 |
| 사건에 반영 | 자료 내용의 반영과 필요한 요약 재확인 요청 | 이미 확인된 사실/증거능력으로 승격하지 않음 |
| 다시 처리 | 기존 실패/재시도 조건에 맞게 처리 | 비용 관측 누락 때문에 사용자가 재승인하는 절차가 아님 |
| 원본 보기/저장 | 허용된 본인 자료의 실제 원본 | PDF 식별정보 가림이 원본을 바꾼다는 뜻이 아님 |
| 삭제 | 대상·영향을 확인한 뒤 기존 삭제 요청 | 닫기/선택 해제와 다른 동작 |

문구와 액션 노출은 실제 지원되는 상태/권한에 맞춘다. 기존 동의 후 자동 처리 의미를
추가 승인으로 바꾸지 않으며 새 모델/처리 API를 이 문서에서 추가하지 않는다.
삭제·권한 상실로 원문을 볼 수 없다면 그 상태를 표시하고 이전 private 내용을 재구성하지 않는다.

## 6. 리포트 화면의 내용과 주요 액션

### 헤더와 본문

리포트 상단에는 작성 기준/시각과 현재 사건과의 차이를 짧게 표시한다. `새 자료 미반영`,
`근거 현재성 확인 필요`, `분석 일부 미완료`, `사용자가 본문 수정`을 단일 완료/실패 표시로 뭉치지 않는다.
본문은 지금 내 사건→지금 준비할 일→주장/사실/증거→쟁점/약점→법·판례/출처 순으로 읽는다.

| 액션 | 위치와 동작 | 보존/제한 |
| --- | --- | --- |
| 변경 내용 반영 | 상단 상태 가까이, 무엇이 바뀌었는지 확인한 뒤 명시 실행 | 요약 재확인 필요 시 그 단계로 연결, 이전 저장본/편집 보존 |
| 본문 편집 | 상단 보조 액션→읽기/편집 전환 | 사건 사실 정본을 바꾸는 기능과 구분, 수정 후 검토/저장 상태 표시 |
| 사실관계 보완 | 관련 절 옆 링크→사실/자료 또는 대화의 관련 위치 | 보고서 문장만 고친 것과 구분 |
| 자료/근거 보기 | 인용·증거 표시→우측 보조 패널의 쪽/시간/발췌 | 본문 스크롤 유지, 자동 재분석 없음 |
| 이 부분 질문하기 | 관련 절→대화 입력에 참조 맥락을 준비 | 자동 전송 없음. 기존 작성 중 메시지는 덮어쓰지 않음 |
| 버전 보기 | 상단 보조 메뉴→저장본 선택 | 현재 사건과 과거 저장본 구분, 예전 본문을 자동 최신화하지 않음 |
| PDF 저장 | 현재 선택 버전의 검토/가림/사진·저장 절차로 연결 | 미저장 편집과 출력 버전을 확인, 다운로드에서 새 AI/법률 조회 없음 |

`이 부분 질문하기`가 이미 작성한 메시지와 충돌하면 새 맥락을 추가할지 기존 입력을 유지할지
보여준다. 사용자가 작성한 문장을 조용히 교체하지 않는다. 다른 화면에서 돌아오면 마지막 절을
복원하고, 명시적 절 링크로 진입한 경우에만 그 절로 이동/강조한다.

### 기존 세 액션의 연결

| 액션 | 이동/결과 |
| --- | --- |
| 직접 해결 | 문서 초안 화면에서 해당 리포트 기준·현재 단계의 문서/기존 초안을 확인. 종류 선택/보기만으로 생성하지 않음 |
| 변호사와 해결 | 미지원 안내 모달만 표시. 연결/선택 저장/공유/외부 이동/AI 실행 없음. 닫으면 버튼으로 초점 복귀 |
| 리포트만 저장 | 선택 버전의 PDF 검토/보관 흐름. 완료 후 같은 사건/리포트로 돌아와 준비 계속 |

과거 리포트에서 직접 해결을 누르면 이전 기준의 저장 초안 보기와 현재 사건 기준 새 준비를
구분한다. stale 상태를 UI 전환으로 해소하지 않으며 새 생성은 현행 guard와 명시 확인을 요구한다.
세 액션의 위치는 본문 다음 준비 영역이다. 상단 PDF 저장은 같은 출력 절차의 바로가기이며
별도 생성/다운로드 경로를 복제하지 않는다.

## 7. 문서 초안 화면의 내용과 주요 액션

### 기본/빈 화면

초안이 없으면 현재 절차/입장/단계에 맞는 문서 카드, 작성할 내용, 필요한 확인 항목을
보여준다. 예: 민사 준비는 소장, 소장 대응은 답변서, 형사 준비는 고소장, 형사 대응은
사실관계·진술 준비 메모. 부적합/미확인 문서나 다른 절차를 UI에서 몰래 확정하지 않는다.
`준비 조건 보기`는 읽기이고 `초안 만들기`는 명시 생성이다. 부족한 자료/공식 근거가 있으면
지금 가능한 사실 정리와 보완 경로를 표시한다.

### 문서가 있는 화면

상단에 제목/종류·작성 중 보관 여부·기준 리포트/시각·미확인 항목 수를 둔다. 내부 ID를
필수 이해 정보로 노출하지 않는다. 같은 이름의 문서라도 작업 중 내용과 검토해 저장한
버전을 구분한다. 작성 중 보관을 검토 완료/제출 준비 완료로 표현하지 않는다.

| 액션 | 동작 | 주의할 상태 |
| --- | --- | --- |
| 문서 선택/다른 문서 | 기존 문서/버전 또는 종류 선택으로 이동 | 작업 중 내용 보관 후 이동, 자동 생성 없음 |
| 근거 보기 | 문장/항목과 연결된 사실·자료·기준 리포트 절을 보조 패널에서 확인 | 연결이 없는 설명은 없다고 표시; 클릭만으로 근거를 만들지 않음 |
| 관련 사실 보완 | 해당 사실/자료 또는 대화로 이동 | 현재 문서 편집·선택 위치 보존, 정본 변경 뒤 갱신 필요 표시 |
| 현재 사건 반영 | 바뀐 기준을 확인→새 후보 준비→차이 검토→선택 적용 | 이전 사용자 편집을 자동 덮어쓰지 않음 |
| 검토 후 저장 | 사실/미확인/사용 자료를 검토한 버전 저장 | 사용자 확인 receipt와 임시 보관 분리 |
| 본문 복사/텍스트 저장 | 검토한 버전의 본문을 기존 검토용 형식으로 보관 | 리포트 PDF와 구분, 새 PDF/DOCX 조판을 제공한다고 표시하지 않음 |

공통 상태를 이중으로 표시하지 않는다. 문서 전체에 대한 임시 보관/검토 상태는 상단 한 곳,
특정 항목의 빠진 내용/근거는 그 항목 가까이에 둔다. 근거 확인은 읽기를 유지하고,
법률 문장을 직접 바꿨다면 이전 분석의 검증 표시가 새 문장까지 보장한다고 표시하지 않는다.

## 8. 네 경로에서 강조할 내용

| 경로 | 대화의 우선 과제 | 자료 패널에서 자주 확인할 것 | 리포트 중심 | 초안 기본 후보 |
| --- | --- | --- | --- | --- |
| 민사 청구 준비 | 원하는 해결·약정·이행/금액 공백 | 계약/약정·거래·지급/반환 근거 | 요구 항목/금액과 사실·증거·공백 | 소장 |
| 민사 청구 대응 | 상대 주장과 다른 본인 설명 | 받은 문서 종류·주장 원문·지급/이행 자료 | 상대 주장과 내 설명의 비교 | 소장 대응 답변서; 다른 문서는 별도 조건 |
| 형사 고소 준비 | 행위·피해·직접 경험/추정 구분 | 대화/사진/녹음 등 원본 위치와 실제 확인 범위 | 행위별 경위·자료·미확인 쟁점 | 고소장 |
| 형사 고소·수사 대응 | 알려진 주장/통지와 본인 경위 | 확보한 문서/통지·상대 말과 기관 문서 구분 | 확인된 범위·내 설명·아직 모르는 범위 | 사실관계·진술 준비 메모 |

배치와 기본 이동 규칙은 같다. 경로마다 앱을 새로 배우게 하거나 자료·리포트 저장을
각각 별도 구현하는 구성을 제안하지 않는다. 문서 선택/생성 조건은 [상세 흐름](../product/CASE-PREPARATION-JOURNEYS.md)을 따른다.

## 9. 왕복 이동과 입력 보존

### 대표 이동

| 시작 동작 | 도착 | 돌아올 때 보존할 것 |
| --- | --- | --- |
| 대화 답변의 자료 인용 | 같은 화면의 자료·근거 패널 | 메시지 위치·미전송 입력·선택 자료 |
| 대화에서 리포트 관련 절 보기 | 리포트의 해당 절 | 대화 입력/읽던 위치·작업 상태. 아직 업로드하지 않은 파일은 아래 명시 선택 적용 |
| 리포트의 증거 확인 | 자료 원문 쪽/시간 | 리포트 절/스크롤·읽기/편집 상태 |
| 리포트의 직접 해결 | 문서 초안 선택/기존 문서 | 선택 리포트 버전·보관/검토 기준 |
| 초안 항목의 근거 확인 | 보조 패널의 자료/기준 절 | 입력·커서/선택 위치·문서 버전 |
| 초안에서 대화로 질문 | 대화 입력의 참조 맥락 | 기존 메시지와 문서 편집 모두 보존, 자동 전송 없음 |
| 자료 교정 후 리포트 확인 | 리포트의 변경 안내 | 자료 교정/현재 사건 반영과 본문 편집의 차이 |
| 브라우저 뒤로/앞으로·직접 URL | 같은 사건의 실제 대상 | 복원 가능한 마지막 위치·안전하게 보관된 작업 중 내용 |

### 이동할 때의 보관 규칙

같은 화면 안의 패널/목차 개폐·자료 읽기는 편집을 remount하거나 저장하지 않는다.
전체 페이지가 바뀔 수 있는 주 작업/사건 전환에서는 안전한 작업 중 보관 계약이 필요하다.
현재 구현에 그 계약이 이미 있다는 주장은 하지 않는다.

1. 읽기만 했다면 보관 확인을 묻지 않고 이동한다. 화면 열기/상태 조회로 false dirty를 만들지 않는다.
2. 편집이 있으면 작성 중 내용과 기준을 안전하게 보관하고 확인된 뒤 이동하는 안이다. 이는 검토 완료/정본 게시가 아니다.
3. 보관에 실패하면 현재 입력을 유지하고 `다시 보관`, `이 화면에서 계속`, `변경을 버리고 이동`을 선택하게 한다. 버리기는 기본 선택이 아니다.
4. 업로드/AI/초안 생성은 서버의 실제 작업 상태를 유지한다. 화면을 떠났다고 작업 완료/취소로 표시하지 않고, 복귀 시 실제 상태를 조회한다.
5. 다른 계정/로그아웃/삭제·권한 상실에는 보안 가드가 우선한다. 이전 사용자 입력·자료를 새 사용자 화면에 남기지 않고 소유 데이터/미정산 기록은 임의 삭제하지 않는다.

아직 업로드하지 않은 브라우저 File/기기 파일 선택은 텍스트 보관만으로 전체 페이지 이동 뒤
복구할 수 있다고 약속하지 않는다. 같은 화면에서 유지할 수 없는 이동이라면 `대화에 머무르기`,
`자료로 추가하고 이동`, `첨부 선택을 해제하고 이동`을 명시적으로 고르는 안이다. 자동 업로드/
자동 전송은 하지 않는다. 자료로 추가는 기존 동의·업로드/처리 고지와 접수 확인 뒤 이어가며,
실패하면 입력/선택을 유지한다. 선택 해제는 실제 기기 원본 파일 삭제가 아니다. 기존 업로드가
접수된 자료는 안전한 파일 ID/작업 receipt로 이어가되, 원본 재선택이 필요한 상태를 사실대로
표시하고 파일명/만료된 기기 경로만으로 복구 성공을 주장하지 않는다.

대화 미전송 입력·첨부 선택, 자료 교정, 리포트 본문/사진/가림 설정, 문서 편집은 각각
보존 대상을 명시해야 한다. 민감 내용을 URL·분석 로그·일반 영구 UI 설정 저장소에 넣지 않는다.
보관 상태의 위치·암호화·수명·동의·원자성·새 API/DB는 [ADR-0020](../adr/0020-procedure-aware-intake-and-working-reports.md)의 후속 계약으로 정한다.

## 10. URL·기존 기능·현재 구현과의 차이

| 대상 | 현재/제안 경로 | 구분 |
| --- | --- | --- |
| 대화 | `/cases/:id` | 현재 경로를 기본 진입으로 유지하는 안 |
| 리포트 | `/cases/:id/reports?mode=conversation` | 현재 conversation 리포트 경로 보존. 기존 `/reports` 저장본 의미도 보존 |
| 문서 초안 | `/cases/:id/drafts` | 새 주 작업 URL 제안; 현재 route/API가 있다는 뜻 아님 |
| 자료 직접 URL | `/cases/:id/files?file=...` | 기존 metadata-only/원본 검토 접근과 대화 복귀 보존. 새 화면에서의 인용은 보조 패널 사용 |
| 요약/타임라인/다음 행동/판례 | 기존 summary/timeline/actions/precedents 경로 | 사건 도구·본문 링크 유지, 직접 열기/복귀 검증 |

대상 파일/초안·버전을 나타내는 경로는 소유권을 재검사하며 case ID만으로 권한을 주지 않는다.
URL에는 사건 원문·파일명·편집 내용·검색어를 넣지 않는다. 새 라우트/쿼리 shape는 제안이며
공유 client의 strict 계약을 여기서 변경하지 않는다.

현재 shell은 자료 패널을 같은 React 트리에서 보존하지만, 대화와 리포트는 별도 Astro
page/island다. 패널 state 보존을 화면 간/새로고침 간 작업 보존으로 확대 해석하지 않는다.
구현 시 기존 섬 구조/owner fence·자료 조회를 재사용하고 안전한 보관/복귀 계약을 선행 설계한다.
새 전역 상태 라이브러리나 SPA 도입으로 해결하기로 결정하지 않는다.

## 11. 상태·오류·접근성

| 상황 | UX |
| --- | --- |
| 자료 없음 | 패널 빈 상태와 자료 추가, 설명만으로 준비 계속 |
| 리포트/초안 없음 | 현재 준비 범위·부족 조건·명시적 준비 액션. 가짜 완성 예시로 대체하지 않음 |
| 부분 분석/출처 실패·만료 | 사실/저장본 읽기와 새 법률 설명의 제한을 구분. 올바른 다음 행동 안내 |
| 생성/반영 중 | 작업을 시작한 위치의 실제 진행 상태, 다른 허용된 읽기는 계속. 불필요한 전체 화면 잠금 없음 |
| 저장 충돌/새 결과 도착 | 현재 편집과 새 버전을 비교/전환, 늦은 결과로 덮어쓰기 없음 |
| 접수 ACK 불확실·연결 오류 | 원래 입력/작업 키 보존, 실제 상태 확인 뒤 기존 재시도. 무조건 새 작업 생성 금지 |
| 재동의 필요 | 새 생성/변경 제한과 기존 본인 저장본의 허용 조회/다운로드·삭제 구분 |
| 삭제·owner 변경 | 기존 보안/비공개·늦은 작업 부활 방지 유지 |

한 화면의 주요 액션은 현재 작업에 맞게 강조한다: 대화는 보내기, 자료 검토는 교정 저장,
리포트는 변경이 있으면 반영/확인 중이면 관련 준비 행동이나 문서 이어쓰기, 초안은 생성 전 만들기/편집 후 검토 저장이다.
자료 추가·화면 전환·부가 도구까지 모두 같은 강조색으로 경쟁시키지 않는다.
키보드/스크린리더의 현재 화면·패널 열림·처리/보관 상태·오류를 알리고 최소44px 주요 조작,
visible focus·reduced motion·긴 한글/파일명·320px/390px/200% 확대를 검증 대상으로 둔다.
내부 Dialog에서 Escape는 가장 안쪽 확인을 먼저 닫고 적절한 opener로 돌아간다.

## 12. 화면 기획 인수 시나리오 (미실행)

| ID | 시나리오 | 확인할 결과 |
| --- | --- | --- |
| W01 | 네 경로의 사건 상세 첫 진입 | 같은 세 작업 화면·절차/입장 표시와 경로별 기본 내용 |
| W02 | 자료 패널을 닫은 상태 | 리포트/문서 초안을 여전히 직접 찾을 수 있음 |
| W03 | 대화 초안·선택 자료를 두고 리포트 왕복 | 미전송 내용/읽기 위치 보존. 미업로드 파일은 실제 보존 가능 여부와 명시 선택, 자동 업로드/전송0 |
| W04 | 리포트 근거 클릭→원문→복귀 | 쪽/시간 위치와 현재 절, 자료 권한 유지 |
| W05 | 문서 편집→근거/기준 리포트/대화 왕복 | 본문·선택/커서·문서 버전 보존, 새로운 답변이 편집을 덮어쓰지 않음 |
| W06 | 다른 화면 이동 중 보관 실패 | 현재 내용 유지, 재시도/머물기/명시적 버림 선택 |
| W07 | 업로드·교정·내부 Dialog 중 resize | 같은 입력/진행 상태, modal 순서/초점/개폐 경계 유지 |
| W08 | 모바일 키보드·자료 보조 화면·뒤로 | 입력 가림/이중 보조 화면 없음, 올바른 내용/초점 복귀 |
| W09 | 오래된 리포트의 직접 해결 | 이전 초안 보기와 현재 기준 새 준비 구분, guard 우회0 |
| W10 | 새 자료/출처 만료/직접 편집·새 결과 도착 | 서로 다른 상태 안내, false dirty·늦은 덮어쓰기·겹친 poll 회귀 없음 |
| W11 | 세 액션·변호사 미지원 모달 | 기존 결정 유지, 선택 저장/연락/공유·AI 실행0 |
| W12 | 새로고침·직접 URL·뒤로/앞으로 | 대상 화면/버전/허용된 작업 중 복구, URL에 원문 없음 |
| W13 | 계정 전환·재동의·삭제·동시 편집 | owner/동의/CAS/삭제 경계와 기존 본인 데이터 권리 유지 |
| W14 | 화면/패널/목차 읽기·다운로드 | 새 모델/법률 호출0, 읽기만으로 canonical 저장/검토 receipt 변경0 |
| W15 | 320/390/768/1024/1440·200%·키보드/긴 제목 | 읽기 폭·조작 영역·focus/scroll와 모바일 입력 보존 |

상세 화면 기획은 이 문서로 리뷰한다. 실제 반응형/브라우저·보관/복구·URL·네이티브
키보드/외부 처리의 인수는 후속 구현 뒤 수행한다. 화면 초안을 구현/법률/배포 성공 증거로 사용하지 않는다.
