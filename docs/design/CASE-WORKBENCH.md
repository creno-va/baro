# 사건 워크벤치 디자인 계약

> 최신 #799 지시의 [Headless 웹 UI 계약](./HEADLESS-WEB-UI.md)과 ADR-0022가 이 문서의 native primitive/라이트 고정/로그인 제외 내용을 대체한다. 사건 작업의 흐름과 아래 공간 구조는 유지한다.

2026-11-10 사용자 첨부 Codex 화면과 직접 지시, GitHub #795 및 후속 밝은 색상·공통 사이드바 지시(#797)가 기준이다.
이 문서는 /new와 사건 상세 웹 UI에 적용한다. 랜딩·로그인과 새 사건 입력 본문 배치는 유지한다.
이전 전면 리디자인이나 네 작업 탭 구조를 다시 적용하지 않는다.

## 구조

- 왼쪽: BARO 로고, 확인할 일·최근 사건 검색, 새 사건 입력(/new), 최근 사건, 하단 프로필.
  내 사건 목록 메뉴·프로젝트·dot·팀 초대·변호사 전용 진입은 없다. 프로필은 기존 계정 설정으로 연결한다.
- 중앙: 56px 사건 헤더, 독립 스크롤 대화, 하단 고정 입력창. 본문은 최대 920px이다.
  메시지를 카드 여러 겹으로 감싸지 않는다. 읽는 순서와 사실·처리 상태의 구분을 우선한다.
- 헤더 오른쪽: 리포트, 사건 도구 더보기, 참고 패널 토글. 리포트는 별도 URL에서 읽고
  사건 대화로 돌아온다. 리포트는 사건 준비 중 수시로 확인하는 문서다.
- 입력창: 본문 입력, 왼쪽 `+`, 오른쪽 보내기. `+`에서 자료 추가·자료 멘션·기존 외부 조회를
  제공한다. 멘션은 실제 업로드 완료 자료의 ID를 기존 메시지 계약으로 전달하며 선택한 자료는
  입력창에 표시한다. 모델·권한·훅·마이크·음성 UI는 넣지 않는다.
- 오른쪽: `지금 확인 / 자료 / 판례`. 실제 실패·처리 중 자료와 오래된/실패 리포트 상태가
  있거나 현재 분석에서 연결되지 않은 보완 자료가 있으면 `지금 확인`을 기본으로 보여준다.
  직접 고른 탭은 상태 갱신으로 바꾸지 않는다.
  실제 알림 백엔드나 읽음 상태가 있는 것처럼 표현하지 않는다.
- 자료 교정과 원본 확인은 오른쪽에서 수행한다. 교정 중 탭 이동은 내용을 보존하며, 명시적인
  닫기·다른 자료 열기는 기존 미저장 확인을 거친다. 판례 검색·원문·비교는 기존 권한·공식 출처
  검증 경로를 사용하고, 탭을 열었다는 이유로 검색/AI 작업을 실행하지 않는다.
- 1200px 미만에서 같은 패널 DOM을 모달 시트로 전환한다. 자료 교정·입력·파일 선택·스크롤을
  리사이즈로 재생성하지 않는다. 모바일에서는 왼쪽 목록을 메뉴로 연다.

## 디자인 시스템

`CaseWorkbenchLayout.astro`와 `.baro-workbench`를 경계로 한다. 기존 AppLayout의 제품 스타일
네 겹을 사건 상세에 가져오지 않는다. 공개·로그인은 독립적으로 유지한다. /new와 사건 상세는 같은 shell과 사이드바를 사용한다.

첨부 화면의 공간 구조는 유지하고, 색상은 원래 새 사건 화면의 밝은 톤을 따른다.
배경 #f6f7f9, 사이드바·입력창 #ffffff, 본문 #0f172a, 보조 텍스트 #667085,
경계 #e2e8f0, BARO primary #2563eb을 두 화면에서 공유한다. 기존 로고 에셋을 그대로 사용한다.
primary는 보내기·선택된 탭처럼 실제 우선순위가 있는 곳에만 쓴다.
별도 리포트는 흰 문서 표면으로 구분하여 기존 읽기·편집 대비를 유지한다.
판례 도구 모듈 로딩 실패는 패널 안에서 안내하고 새 탭 대안을 제공하여 대화 입력을 보존한다.

본문 15px/1.8, 보조 정보 12~13px, 사건 제목 16px, 패널 제목 18px을 기준으로 한다.
4/8px 간격 리듬, 메뉴·컨트롤 8px, 팝오버 14px, 입력창 24px radius를 사용한다.
데스크톱 보조 아이콘은 36px, 좁은 터치 화면의 주요 조작은 44px 이상 확보한다.
키보드 초점·hover·선택·비활성·실패·로딩을 구분하며 reduced-motion을 따른다.

[Headless UI Menu](https://headlessui.com/react/menu)와
[Dialog](https://headlessui.com/react/dialog)의 비스타일 접근성 원칙을 참고한다.
새 라이브러리 의존성 대신 기존 native details/dialog와 검증된 공통 Dialog의 키보드·초점 처리를
유지한다. [토스의 가치 우선 원칙](https://toss.tech/article/value-first-cost-later)을 사건 준비에
적용하여 지금 확인할 내용과 그 이유를 먼저 보여주고, 세부 도구는 필요할 때 펼친다.

## 변경하지 않는 계약

owner/session 경계·업로드 동의·재전송/idempotency·교정 CAS·private 자료·리포트 snapshot과
초안 검토 저장·API/DB/공급자·AI200/일·질문 2×3을 유지한다. 자동 전송·가짜 자동 저장·
알림 카운트·추정 기한을 추가하지 않는다. 비용 관측 누락은 기능 차단으로 전파하지 않는다.
리포트의 `직접 해결 / 변호사와 해결 / 리포트만 저장` 세 액션과 변호사 미지원 모달은 유지한다.
production은 이번 작업의 배포 대상이 아니다.

## 검증

1848·1440·1024·390·320px에서 헤더/입력창/패널의 실제 위치·스크롤·겹침을 확인한다.
자료 멘션·추가/동의·원문 교정·미저장 닫기·리사이즈·판례 원문·리포트 왕복·프로필·검색·
owner 변경 시 private 내용 제거를 검증한다. 랜딩·로그인 시각 구성과 새 사건 본문 구성을 diff로 확인한다.
정식 진입은 /new이며 /app은 인증·동의 경계를 거쳐 /new로 연결한다.
/new와 사건 상세에서 같은 사이드바 구조·색상, 내 사건 메뉴 부재를 검증한다.
설치·quick·build·브라우저 검증 및 PR/CI/배포 결과는 실행 기록에 실제 상태로 남긴다.
