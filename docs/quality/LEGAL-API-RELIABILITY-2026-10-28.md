# 법률 조회 간헐 실패 정비

범위: #569, `codex/569-legal-reliability`, 기준 main `71ead5976ce2379996f8f733633310fa03a30a3b`.
외부 API의 상시 가용성을 보장한다는 인수는 아니다. 랜딩·새 공급자·모델·DB migration·비용
정책을 바꾸지 않으며 API 키/스토어 보류와 보안 high2·실제 legacy unknown 기록을 보존한다.

## 수정 계약

- 법령의 요청 조문과 판례의 개별 원문을 각각 검증·저장·인용 연결한다. 한 원문 실패 때문에
  다른 검증 원문을 버리거나 요약본까지 검증 원문으로 올리지 않는다. 정상/제한 원문을
  나눠 보존하고, 반환한 원문이 검증됐더라도 실패한 다른 원문이 있으면 부분 확인으로 표시한다.
- 판례 목록의 잘못된 개별 행은 별도 실패로 남긴다. 전체 목록 형식/건수 이상과 중복 식별자는
  거절하며, 법령의 시행 이력 완전성·날짜·원문 ID/법원/사건번호·hash/권한 검증은 유지한다.
- HTTP429/5xx의 `Retry-After`는 초 또는 HTTP 날짜로 해석한다.
  [RFC9110](https://www.rfc-editor.org/rfc/rfc9110.html#name-retry-after)의 대기 지시를
  무시하고 즉시 반복하지 않는다. 기존 최대3시도와 기본10초×3+100/200ms 대기 상한 안에서
  처리하며, 대기 지시가 상한을 넘으면 제한 상태를 반환한다. 외부 취소와 지연된 권한 확인도
  상한 뒤의 새 외부 요청을 허용하지 않는다. 전체30회/workspace·research12회 상한을 유지한다.
- 판례 검색 응답의 `availabilityIssues`는 `x-baro-legal-diagnostics: 1`로 요청한 클라이언트에만
  제공한다. 기존 strict 클라이언트의 응답 형태와 구버전 서버 소비를 보존한다. topic과 유한
  reason enum만 포함하며 임의 오류·URL·키·사건 진술은 전달하지 않는다.
- 웹/모바일은 연결 지연·요청 제한·본문 형식/무결성·공식 안내 개정 대기를 구분한다. 대화의
  서버 경고에도 같은 이유를 적용한다. 부분 확인된 판례와 빈 검색 결과를 장애와 구분한다.
- 만료/변경된 판례 조회권의 웹 재시도는 사용자 요청에 의한 새 검색으로 전환한다. 만료된
  같은 token을 반복하거나 원문 검증·소유권·revision fence를 생략하지 않는다. 비교 접수에서
  만료가 확인되면 이전 token의 재접수를 막고 새 검색을 제공하며, 이미 접수된 작업/유실 응답
  복구와 idempotency key는 유지한다. 자동 재검색이나 새 유료 비교를 실행하지 않는다.
- 운영 진단은 느린 요청/실패의 endpoint enum·시도·시간·HTTP status·reason 및 부분 결과의
  검증 원문 수만 기록한다. 미지의 필드와 임의 endpoint/reason은 거절한다. query·원문·OC·
  token·개인정보·SQL·exception을 로그에 쓰지 않으며 진단 실패는 제품 결과를 바꾸지 않는다.
- 제한/실패가 하나라도 있는 진단을 전체 readiness 성공으로 표시하지 않는다. 개정 대기
  안내는 계속 인용 제외하며, 오래된 cache·모델 기억·다른 공급자로 빈 내용을 채우지 않는다.

## 검증 기록

기존 코드의 고정 공개 샘플 진단40635578163은 preview secret/GitHub runner에서 법령·판례
5요청 HTTP200,3원문 검증 성공이었다. 법령 목록 헤더 수신6467ms를 관측했으나 특정 사용자의
운영 실패 원인이나 이 후속 수정의 live 성공 증거가 아니다. 당시 공식 안내는 개정 대기였다.

후속 검증은 실제 검사한 SHA와 실행 결과를 #569/PR/#71에 구분해 기록한다. 로컬 fixture,
GitHub runner의 공식 서버 응답, deployed Worker와 사용자 화면의 실제 성공을 혼동하지 않는다.

회귀 범위: 정상/실패 순서 교환, HTTP/timeout/요약본/식별 불일치/목록 오류가 섞인 판례,
일부 조문 실패, 최종 권한 철회, 살아남은 원문의 실제 인용 검증, 요청 제한 대기/취소/시간
상한, 진단의 비민감성, legacy wire와 client opt-in, 만료 조회권의 새 검색 복구, 브라우저 상태.


전체 검사40646732518에서 과거 성능 검증의 전체 폐기 기대3건을 발견했다. 후속 검증은
역사적 baseline SHA/실험 코드를 보존하고 정상 경로의 출력 동등성도 유지한다. 현행 제품의
terminal 조문 실패만 별도 per-original 계약으로 명시해 정확히598/603조의 hash·날짜·원문을
검증한다. 만료 cache의600조는 재사용하지 않으며 살아남은 조문은 새로운 확인 시각과
binding을 갖는다. 예약 거절 후 실제 추가 HTTP가 없음을 검사한다. benchmark의 이 차이는
출력 동등성 성공으로 숨기지 않고 결과에 별도 표시하며, 해당 회귀를 법률 전용 PR CI에 포함한다.
