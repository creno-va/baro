# 2026-10-31 자료·AI 재개와 정책 내용 검토

사용자 요청 범위는 업로드 지연 개선, 화면 이탈 후 AI 처리 지속·복귀 동기화,
한국 시간 조회 도구, 정책 내용 정리·목차 제거와 동의 취소 액션 제거다.
`codex/upload-processing-policy`에 로컬로 누적하며 원격 CI·PR·병합·배포는 다음 지시를 따른다.

## 확인한 운영 사실

- 로그인된 Wrangler OAuth의 BARO 계정 권한으로 양쪽 D1을 읽기 전용 조회했다.
  셸에 남아 있던 다른 계정 ID는 요청 프로세스에서 BARO 계정 ID로 명시했다.
  DB 연결·데이터·공개 설정·키는 변경하지 않았다.
- production의 해당 집계 시점에는 v2 작업이 없었다. preview에서 `file_processing`
  분류 11건이 완료됐고 created_at→updated_at 평균은 81.5초였다.
  이 분류에는 업로드 형식 probe와 해석 작업이 함께 들어가므로 전송 시간이나
  사용자 전체 대기 시간으로 해석하지 않는다. 파일 5건은 ready였고 진행 중 파일은 없었다.
- 집계 SQL 실행 시간은 1ms 미만이었다. 이것은 개별 업로드의 모든 쿼리가 빠르거나
  Cloudflare/R2/Container에 지연이 없다는 증거가 아니다. 실제 인증된 전송의
  개선 전후 종단간 수치는 아직 측정하지 않았다.

## 구현

- 웹 파일을 한 번 읽으며 전체/조각 해시를 준비한다. 8MiB 이하 파일은 전체 해시를
  조각 해시로 재사용한다. 큰 파일은 첫 조각으로 암호화 envelope를 확정한 뒤
  최대 3개 조각만 동시에 전송한다. 원본·manifest 순서·해시·정수 용량·권한 검증은 유지한다.
  한 요청이 실패하면 진행 중 요청이 끝난 뒤 reader를 정리하고 새 조각을 보내지 않는다.
  native adapter는 기존 순차 기본값을 유지한다.
- 새 예약 뒤 중복 목록 조회를 제거하고 전송 전 독립 권한 조회를 겹쳐 기다린다.
  각 body 읽기 전·R2 전송 전·저장 공개 전의 실제 재검사는 생략하지 않는다.
  preview 예약/조각/완료 응답에는 숫자와 유한 enum만 담는 Server-Timing을 추가했다.
- 사건/판례 비교 접수는 저장된 작업·outbox를 기준으로 즉시 응답하고 Workflow 생성은
  request waitUntil에서 시작한다. 이미 시작한 AI는 HTTP 연결과 독립적으로 실행된다.
  실패한 시작은 매분 같은 immutable runtime ID로 재조정한다. 정리 작업의 예외가
  후속 작업을 건너뛰지 않게 하고 v2 dispatch를 먼저 확인한다.
- 화면의 polling은 숨겨진 탭에서 읽기를 쉬고 visibilitychange/pageshow/online 때
  즉시 서버 상태를 재조회한다. 일반 API의 무한 연결 대기는 30초로 제한하고
  원본 전송·파일 완료 검사·내보내기는 300초 기술 한도를 유지한다.
  HTTP 읽기 timeout은 서버 작업 취소가 아니며 idempotency·소유권 검사는 유지한다.
- `current_time`은 서버 Date에서 UTC·Asia/Seoul 날짜/시각을 반환하는 로컬 도구다.
  외부 공급자·키·추가 개인정보 전송은 없다. 모델이 요청하면 결과를 다음 생성과
  독립 검수에 함께 제공하며 같은 응답에서 반복 조회하지 못하게 한다.
  지연된 작업의 ‘어제/내일’은 원래 요청 calendar 기준을 보존하고 법정 기한 계산에 쓰지 않는다.
- 동의 화면 취소 링크를 제거한다. 로그인 상태를 브라우저에서 읽는 폼은 초기 SSR 대신
  상태 안내 fallback과 client-only hydration을 사용해 첫 렌더의 불필요한 React hook 오류를 피한다.

화면 닫기 전에 아직 전송하지 않은 파일 bytes나 미전송 초안이 서버에서 자동 실행된다고
주장하지 않는다. 이 변경의 지속성 보장은 서버에 접수·저장된 AI 작업에 적용된다.
실제 공급자 거절·삭제·권한 철회·필수 동의 미수락·기술 한도로 실패한 작업은 실패로 남긴다.

## 검증 범위

- 순서가 뒤바뀐 동시 조각 전송을 실제 signed HTTP·SQLite·AES·대체 R2로 완료하고
  최종 전체 원본 digest와 비교했다. 전송 실패·계정 변경·손실 응답 복구도 확인했다.
- 기존 파일/작업의 재시도·폐기된 lease·동의 철회·삭제와 게시 시점 경합 회귀를 확인했다.
  모델 호출과 공급자 응답은 합성 대역이며 유료/실제 모델 호출은 하지 않았다.
- 브라우저는 정책 320px/200%, 동의 데스크톱·모바일, 탭 복귀 즉시 반영과 일시 읽기 오류
  후 복구의 4개 시나리오만 수행했다. 동의 첫 SSR hook 오류는 client-only 폼으로 수정 후 통과했다.
- 제품·도구 TypeScript, 공통 client TypeScript, Astro 검사(0 errors), 변경 파일 lint와
  문서 링크 검사 통과. 전체 CI·전체 UI suite·원격 배포는 실행하지 않았다.
- 실제 사용자 네트워크·실제 큰 파일의 개선 전후 시간, 탭 종료 중 실제 유료 AI 실행은
  이 로컬 검증의 증거 범위가 아니다. 서버에 이미 접수된 durable 작업의 실행/상태 복구를 검증했다.
