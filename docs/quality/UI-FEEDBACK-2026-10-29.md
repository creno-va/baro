# 사용자 UI/UX 피드백 반영 (#574)

2026-10-29 KST. `codex/574-ui-feedback`는 main `3f3b77d`의 선행 법률 조회
PR570–573와 CI 성공을 확인하고 별도 managed worktree에서 진행한다.
기존 배포 세션에 사용자 승인으로 작업 범위와 경로를 전달했으며 main checkout을 수정하지 않는다.

## 동작

- `/cases` 목록 화면은 제거하고 기존 URL은 `/app`으로 302 이동한다.
  사건 조회는 사이드바의 전체 사건 제목 목록에서 수행한다. 기존 5개 제한을 없애고
  독립 스크롤과 계정 소유자 검사, v1/보관/진행 중 사건 재개·삭제를 보존한다.
- 고객 상단 메뉴는 새 사건 입력·변호사 찾기만 제공한다. 계정 설정은 하단 프로필로
  접근한다. 이용 유형 변경·도움말 링크와 settings의 사건 목록/중복 조회를 제거한다.
- 모바일 웹 사건 메뉴는 한 줄 가로 rail이다. 현재/키보드 초점 목적지를 자동 노출하고
  가로 스크롤 안에서 여섯 목적지를 모두 제공한다. 로그인 소개·중복 안내를 줄인다.
- 상세 사실은 질문·답변 중심으로 표시한다. 불확실·불리·상충 진술은 그대로 표시하고
  출처/확인 상태와 원본 링크는 접어서 제공한다.
- 개인/기업 입력 예시·placeholder·준비 안내와 상세 유형을 구분한다.
  암호화된 소유 사건의 subjectContext를 실제 모델 맥락에 전달한다. 기업 선택만으로
  고용·계약·대리권을 추정하지 않으며 기존 질문 2차례×3개 한도는 유지한다.
- 판례 검색/공식 원문/동의·owner/revision/AI quota 계약은 유지한다.
  기존 8개 증거 지표마다 +12.5점, unknown/no는 0점, 고정 분모 8과 정수 반올림을
  사용자에게 표시한다. 승소율을 산정하지 않는다. 지표 버튼은 양쪽 근거와 이유를 열고
  원문에서 정확한 UTF-16 인용 위치·문구가 일치하는 yes 근거만 파란색으로 표시한다.
  겹친 인용은 모든 관련 이유를 유지하며 원문 문자를 수정하거나 HTML을 삽입하지 않는다.
  선택한 판례와 과거 비교 결과가 다르면 이전 결과임을 표시한다.

- 추가 사용자 요청으로 리포트 웹 검토 본문을 번호·제목·사실·출처로 구조화하고
  HTML 및 실제 Workers PDF의 서체 크기·구획·여백·페이지 표시를 정리한다. 원문·가림·
  사진 선택·생성 기준·리비전 계약은 유지한다. 같은 section parser를 사용한다.
- 최종 사용자 지시: 모든 변경과 검증 뒤 PR을 병합하고 preview에만 배포한다.
  이 작업의 변경은 production에 배포하지 않는다.

## 검증 경계

검증 결과는 PR에 실제 실행한 항목과 함께 기록한다. 합성 입력/공식 출처 fixture의
로컬 성공을 실제 provider 응답·OAuth·production 배포 성공으로 확대하지 않는다.
랜딩 코드/자산/스타일, DB schema, 모델/공급자, 비용 정책, 원장/hold와 기존 운영 gate는
변경하지 않는다. 기존 #569 배포·#71의 외부 인수와 독립적인 UI 작업이다.
