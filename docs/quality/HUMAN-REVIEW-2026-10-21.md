# 2026-10-21 휴먼테스트 후속 수정

사용자 제공 12쪽 리뷰를 #302 / PR303의 후속 범위로 처리한다. 랜딩의 소스·자산·스타일은
변경하지 않는다. 아래 검증은 합성 입력과 로컬 API/SQLite/R2 대역을 사용하며 실제 OAuth,
공급자 음성 인식률, preview/production의 응답 시간이나 배포 인수를 의미하지 않는다.

활성 요약의 ‘저장하고 적용’은 서버의 기존 저장→확인 계약을 사용한다. 저장된 정확한
revision을 확인하며, 확인 요청만 실패하면 저장을 반복하지 않고 확인만 재시도한다.
최초 intake의 사용자 확인 절차, CAS·멱등 재시도, 동의와 소유권 조건은 유지한다.

자료의 처리 완료와 사실 정리는 별도 상태다. 새 반영 동작은 사용자가 지정한 현재 자료를
기존 대화 처리에 전달한다. 긴 자료의 일부만 모델이 참고할 수 있음을 표시하며, 자료별
원문·포함/제외·교정과 저장된 리포트의 역사적 출처는 보존한다. API mock의 자료 연결도
명시적 합성 처리이며 실제 모델 성공으로 표시하지 않는다.

## 검증 증거와 남은 실제 확인

Bun 1.4.0의 `bun ci`, `validate:quick`, `validate:build`를 통과했다. 관련 단위94개와
브라우저72개(아래 새 흐름6·자료10·기존 고객43·셸9·최종 Worker CSP4)를 확인했다.
기존 고객 회귀의 실패 항목은 주입 경계/버튼 명칭을 수정한 뒤 좁혀 재검증했으며,
셸 실행에서 조건부로 건너뛴 변호사2개는 통과 수에 포함하지 않는다.

- `tests/browser/human-review.e2e.ts`: 활성 요약 저장·실패 복구·탭 복귀, 포커스 중 DOM/초안/스크롤,
  자료 교정 후 반영/재접속, 사건 삭제, 합성 녹음 재생/로그아웃 회귀. 320/768/1024/1440px 확인.
- `tests/browser/file-review-loading.e2e.ts`: 10개 자료 조회·변경·소유권·동의·늦은 응답 회귀.
- 기존 customer-completion / customer-recovery-intake / intake-saved-review와 shell-integration 회귀.
  응답 유실은 lazy transport factory에서 실제 성공 응답을 유실시켜 주입 여부와 단일 revision을 검사.
- `tests/human-review-client.test.ts`: 요청 병합·완료 후 권한 갱신·장애 재시도·목록 병렬 시작.
- `tests/files-review.test.ts`: 실제 SQLite/AES 저장 교정과 제외가 새 대화 context와 리포트에 반영되는지,
  원본·위치·coverage·삭제 경계가 유지되는지 확인.
- 기존 리포트 출처/감사, workspace client·목록/API·세션 검사와 필수 quick/build 결과는 #302에 기록.

원본 녹음이 제공되지 않아 리뷰 사례의 인명/금액 ASR 오인식을 재현하거나 인식률 개선으로
판정하지 않는다. 모델·공급자는 변경하지 않았으며 실제 녹음의 원문 대조가 남는다.
실제 서버 지연은 serving SHA/환경의 인증·API·D1 구간을 측정해야 한다. 로컬 요청 수 절감은
production 지연 해결 증거로 확대하지 않는다. 배포와 실제 재시험은 해당 SHA의 별도 receipt로 남긴다.
