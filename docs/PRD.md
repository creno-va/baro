## 1. 제품 정의와 현재 상태

BARO는 고소·청구를 준비하거나 상대방 주장에 대응하는 사용자가 대화 안에서 사건과
증거를 정리하고, 공식 근거에 연결된 분석·리포트를 검토해 다음 행동을 선택하도록 돕는다.
초기 제품에서 변호사 연결·전용 사용자 단은 제외한다. 사건 준비 중 리포트를 반복 확인하고
목적별 검토 초안을 보완하는 흐름을 기획한다. 직접 준비와 PDF 보관은 사건 종료 분기가 아니다.
리포트의 직접 해결/변호사와 해결/리포트만 저장 세 액션은 유지하며 변호사 액션은 미지원 안내
모달만 연다. 실제 연결·선택 저장·외부 이동·공유/AI 실행은 하지 않는다. 사건 자동 전달·대리 제출이나 수임 결정도 하지 않는다.

이 문서는 공통 사건 사용자 중심의 새 목표다. 기존 v2 사건·자료·채팅·변호사 기능은 PR167로 main에
통합됐으며 기존 v1 읽기·삭제를 보존한다. 현재 공개 서비스와 운영 정비를 유지하면서
ADR-0018의 사용자 지정 개편을 진행한다. 이번 범위 밖의 신규 확장 중단과 비용 관측 전용·
저장·릴리스 증거·디렉터리 검색 정비는 유지한다. 구현과 실제 외부·운영 인수는 별개다.
[실행 기준](./development/EXECUTION.md)과 GitHub가 실제 진행 상태의 정본이다.

BARO는 변호사나 법률사무소가 아니며, 수임·법률 판단·소송 전략을 대신하지 않는다.
초기 서비스는 무료이며 변호사 소개·중개 수수료를 받지 않는다. 수수료 부재만으로
적법성을 단정하지 않는다. 확대된 제품과 공개 문구의 법률 검토·정책 승인 근거는
현재 미완료다. 정책 초안·사업자 플레이스홀더는 #20/#70의 초안 인수 범위로 수용됐으며,
현재 공개 운영 허가와 독립 외부 검증·실제 법률 승인은 각각 구분한다.

## 2. 대상과 해결할 문제

대한민국 법률이 적용되는 개인과 기업의 사건을 대상으로 한다.
민사·형사·가사·노동·행정·상사·조세 등 대한민국 사건 유형 전체를 탐색·사실 정리와
근거 기반 분석의 범위로 삼는다. 지원 유형을 개인 간 대여에 다시 한정하지 않는다. 개별 법률 쟁점에
필요한 공식 자료를 확인하지 못하면 해당 쟁점의 설명을 제한하고 확인 필요를 표시한다.

기업 사건도 작성자 한 계정이 소유한다. 팀 공동 편집·사내 권한 위임은 이번 범위에
없다. 별도의 연령 제한·연령 확인 항목은 두지 않는다. 법령상 법정대리인 동의가 필요한 개인정보 처리 요건은 개인정보 처리방침을 따른다.
변호사 디렉터리·공개 프로필·연락은 새 목표에서 제외한다. 사건·자료는 로그인과
현재 필수 동의 후 생성한다. 과거 데이터 조회·삭제는 재동의 전에 가능해야 한다.

사용자는 사실과 자료를 흩어 보관하고, 무엇을 확인하고 어떤 문서를 준비할지 모른다.
BARO는 사실의 출처와 확인 상태를 유지하며 사건 이해·자료 보완·초안 작성·반복 검토를 연결한다.
민사/형사와 준비/대응의 4경로·문서 우선 시작은 검토용 제안이며 지원 분야 축소 결정은 아니다.

## 3. 제품 원칙

1. 사용자 진술·자료에서 추출한 내용·공식 자료·AI 정리·추론·확인 필요를 구분한다.
2. 유리하거나 불리한 사실과 모순을 모두 보존한다. 승소를 보장하거나 불리한 자료를 숨기도록 유도하지 않는다.
3. 공식 법령·공식 판례·공식기관 안내만 검증된 법률 근거로 사용한다.
4. 검증 전 모델 출력은 표시하지 않는다. 근거가 없는 법률 설명은 제외하거나 확인 불가로 표시한다.
5. 실제 변호사 연결·전용 사용자 단·외부 플랫폼 소개를 초기 범위에 두지 않는다. 리포트의 변호사 액션은 미지원 모달만 표시하며 성과를 보장하지 않는다.
6. 사용자를 대신한 제출·신고·협상·메시지 발송·결제는 하지 않는다.
7. 원문·결과·자료 내용은 로그·제품 분석·GitHub artifact에 넣지 않는다.
8. 개인정보를 줄여 모델에 전달하고, 전달 자료는 사용자가 검토·수정·마스킹·제외할 수 있게 한다.
9. 삭제·권한·비용 기록·출처 실패를 실제 UI 와 서버에서 함께 처리한다. 비용 금액·관측 누락/만료·월할당·수동 갱신·비용 IO로 기능을 차단하지 않는다.

## 4. 핵심 흐름

```text
목표: 공개 홈 → 공통 로그인·동의 → 사건 설명 또는 보유 문서에서 시작
     → 필요한 사실 확인·사용자 요약 확인 → 사건 작업공간
     ↔ 대화·자료 검토·공식 근거 분석 ↔ 사건 리포트·목적별 초안
     → 선택 버전 검토·PDF 보관 → 사건 준비 계속
문서 입력·질문 생략·분야별 문서의 구체적 흐름은 검토용 제안
```

사건 목적, 개인/기업 맥락, 분야·형민사와 절차 단계는 서로 다른 정보다. 옛 사건의 입장을
추정해 확정하지 않는다. 법률 분석·검토용 초안은 검증된 공식 원문·권한·인용 binding과
독립 감사를 통과한 범위에 한정하며 불명확한 적용·절차·기한은 확인 필요로 표시한다.
변호사 연결은 초기 제공 목표에서 제외하며 사용자 대신 법적 판단이나
외부 실행을 확정하지 않으며 법률 승인·공개 gate는 구현 인수와 구분한다.

## 6. AI 와 자료 처리 경계

2026-10-07 사용자 정정에 따라 초기 서술 뒤 후속 질문 생성은 최대 두 차례로 제한하고,
각 차례에는 최대 세 문항을 제공한다. 1차 질문으로 사건의 큰 상황을 확인하고 그 답변에 따라
2차 질문에서 세부 내용을 확인한 뒤 요약으로 진행한다. 더 필요한 내용은 요약의 미확인 사항에
남기고 요약 확인 이후 채팅에서 이어간다.
질문은 답변에 따라 달라지고 모름·건너뛰기·중단·저장·재개를 지원한다. 웹 canonical 요약은
raw text로 직접 편집하지 않는다. 사용자가 다른 부분을 설명하면 AI가 변경안을 제시하고,
같은 기준 revision의 변경안을 사용자가 재확인한 뒤 정본을 갱신한다. 구형 설치 client의
기존 편집 API·저장 이력은 보존한다. 사용자 확인은 사실의 진실성이나 법률 승인이 아니다.

기존 준비 행동의 자료 보유·출처·일시 확인과 상담 질문 정리는 유지한다. ADR-0018의 명시적
개편에서는 근거에 연결된 법률 분석·취약점/대응점과 절차별 검토용 문서 초안을 허용한다.
공식 절차·서식 근거가 없으면 사실 정리 초안으로 범위를 표시하고 소장·답변서·항소 서류가
완성됐다고 표시하지 않는다. 법적 주장·협상·제출 여부와 전달 대상은 사용자가 판단하며
자동 제출·연락·대리, 결과 보장과 근거 조작은 금지한다. 공개·독립 법률 승인은 별도다.

업로드 때 자료 내용과 외부 AI 처리 동의를 설명하고, 동의한 자료의 자동 분석을 시작한다.
사용 횟수·파일 물량·물리 용량·외부 서비스 장애 때문에 처리를 보류하면 이유·재개 시점/행동을
명시한다. 비용 금액·가격/FX/funding 누락/만료·월할당·refresh·비용 IO는 보류 사유로 사용하지 않는다.
무음·손상·암호 보호·지원 불가 형식·누락 페이지 등은 확인 범위로 표시한다. 파일 내용은 비신뢰 입력이다.

영상은 전체 음성 전사와 1초 간격 및 장면 전환 시점의 프레임 확인을 조합한다.
이는 매 프레임의 내용을 검증했다는 뜻이 아니다. 처리된 시간·페이지·구간, 제외·실패
구간, 추출 방식과 불확실성을 보여준다. 자동 추출은 원본 진정성·증거능력의 보장이 아니다.

| --- | --- |
| 사건 자료 | 최대 100개, 원본 합계 5GB |
| 문서·이미지 한 파일 | 최대 100MB |
| 음성·영상 한 파일 | 최대 1GB 및 60분 |
| PDF 한 파일 | 최대 500쪽 |
| 계정 저장 | 원본·파생물·리포트를 포함해 최대 10GB |
| KST 하루 | 새 사건 3개, 사용자 AI 응답 200회, 음성/영상 자동 처리 합계 60분 |
| 애플리케이션 비용 | 관측 전용(`APPLICATION_COST_LIMITS_ENABLED=false`); 금액·가격/FX/funding 누락/만료·월할당·refresh·유지비·비용 IO로 기능/배포 차단 없음; 실제·추정·미정산 기록 보존 |

제품 한도는 decimal MB/GB로 표기하고 서버는 bytes로 같은 경계를 검증한다.
내부 파일 파생물은 계정 저장량에 포함하며 완료 시 예약량과 실제량을 정산한다.
동일 논리 작업의 시스템 retry는 사용자 quota를 중복 차감하지 않지만 실제 처리 비용은
모두 ledger에 기록한다. 외부 호출은 정확히 한 번 과금을 보장하지 않으므로 durable
attempt·멱등성·시도 횟수·실행 물량 검사를 유지한다. 비용 예약·미정산·정산과 재원 관측값은
기록이며 비용 누락/만료·월할당·승인/refresh·IO 예약이나 금액으로 admission·dispatch·
preflight·배포를 막거나 동결하지 않는다. [현행 정책과 구현 잔여](./operations/PREBETA-COST-POLICY.md)를
구분하며 사용자 재지시 전 비용 차단을 재도입하지 않는다.
기존 미정산을 삭제하거나 0원으로 바꾸지 않는다. 기존 사용자 설정 $10/$30 자동충전 외
새 결제·충전 변경은 별도 결정이며 외부 공급자의 실제 거절은 오류로 처리한다.

## 8. 리포트와 보관·삭제

PDF는 사용자가 확인한 요약·경과·사실·자료 목록·출처/시간·모순·미확인 점·준비 행동을
포함한다. 사용자 식별자는 기본 유지하되 내보내기 전 검토·수정·마스킹·제외를 제공한다.
모델 전송 최소화와 사용자 전달용 리포트의 식별자 정책은 별개다. 원본 ZIP 에는 사용자가
선택한 원본만 포함하고, 마스킹되지 않은 원본임을 선택 단계에서 알려준다.

새 자료나 사실 수정은 revision 과 리포트 버전을 바꾸며 이전 생성물을 최신 사실처럼
표시하지 않는다. 과거 리포트는 생성 기준 revision 과 시각을 보여준다.
사용자는 HTML/PDF/ZIP을 다운로드해 직접 전달한다. 플랫폼이 변호사에게 사건을 자동 공유하지 않는다.
HTML은 2026-10-09 사용자 결정에 따른 제품 범위다(#66/UI-35). 저장된 리포트의 내용·생성 기준·
마스킹·자료 제외를 유지하고 모바일/인쇄를 지원하며, 입력 HTML이나 외부 script를 실행하지 않는다.

사건은 사용자 삭제까지 보관한다. 사건/자료/계정 삭제는 원본·파생물·모델 context·채팅·
Workflow 상태·리포트·임시 export 와 관련 공개 자산에 적용한다. 삭제 요청·실제 정리 상태를
구분하고 백업 복구 후 삭제 journal을 재적용한다. 상세 보존·복구 조건은 승인된 정책과
[보안 명세](./security/SECURITY-PRIVACY.md)에 맞춘다.

## 9. 디자인과 기술

Astro·React islands·Tailwind·Hono·Workers·D1·Workflows를 유지한다.
무거운 자료 처리는 격리된 Containers 에서 수행하고 원본/파생물/리포트는 R2에 보관한다.
웹/API는 Workers 이며 Node 파일시스템·process 예외는 격리 처리 서비스에만 적용한다.
기존 모델·reasoning·Unified Billing 경계를 유지하고 Whisper 음성 경로를 추가한다.
실제 catalog·vision·ASR·크기/시간·보존 지원은 live 검증 전 확인 완료로 주장하지 않는다.

shadcn 기반 컴포넌트, 파란색 primary, Lucide, Pretendard 와 공통 SVG 로고를 사용한다.
페이지 수는 고정하지 않고 업무 흐름에 맞게 재구성한다. 구체적 화면 상태·경로·접근성은
[UX 명세](./product/UX-SPEC.md), 결정은 [ADR](./adr/README.md)을 따른다.

## 10. 완료와 성공 기준

개발 완료는 페이지 존재나 테스트 통과만으로 판단하지 않는다. 기존 변호사 계정을 포함한 공통 사건 사용자가
배포된 실제 UI 에서 모든 MVP 기능을 끝까지 시연하고, 재접속·권한·quota·실패·
삭제와 실제 외부 연동·파일 다운로드·모바일·키보드·CSP를 확인해야 한다.
[시연 행렬](./product/UI-DEMONSTRATION.md)의 각 행은 동일 candidate SHA의 증거를 요구한다.

운영 지표는 질문/요약 확인 완료율, 자료 처리 coverage 와 실패율, 사실 정리·내보내기
완료율, 리포트 반복 검토·자료 보완·초안 준비의 성과, 처리 시간·비용·삭제 실패를 검토한다.
새 지표는 기획 제안이며 현재 수집 구현을 뜻하지 않는다. 사용 기록은 별도 동의 UI 없이 탭 안에서만 기본
기록하며 외부로 전송하지 않는다. 민감 입력·자료명·원문·검색어·연락처·실제 계정 식별자를
기록하지 않으며 탭별 무작위 식별정보와 기존 allowlist를 유지한다. 새 목표 수치는 실제 표본 후 결정한다.

변경별 검증 후 최종 main SHA의 전체 회귀를 수동 GitHub workflow로 수행하고 같은 SHA를
preview 제한 smoke와 production에 사용한다. production 운영자 승인은 hyunhomon 또는
hwangeunchan의 정확한 SHA 기록이며 최대24시간 유효하다. 기존 정식 공개 checker의 미완료
정책·외부 조건은 보존한다. API mock UI(M6 완료 이력), 실제 기능·인수(M5), 전체 실제 인수
(#71)를 구분한다. 정비 완료로 #71을 조기 종료하지 않는다. 현재 기준은 [ADR-0015](./adr/0015-maintenance-and-operating-policy.md)다.
